## 3. 미분류 특성 (카탈로그에 없음, 카탈로그는 고치지 않음)

카탈로그로 다룰 수 없는 성격 세 가지가 이 프로젝트의 중심이다. 아래 관점·리스크 초안을 P2~P7에서 코어 관점에 더해 쓴다.

### U-1 근거 기반 생성 (검색 증강 생성)
- **PM 관점**: `근거 연결 | 답변의 모든 주장이 검색된 청크에서 나오는가, 인용이 실제 검색 결과에 있는가` / `근거 부족 판정 | 언제 답하지 않고 "정보 부족"을 안내하는가, 그 기준을 무엇으로 정하는가(개발용 문항)` / `실패 구분 | 검색 실패·모델 오류·정상 "근거 없음"을 사용자와 기록에서 어떻게 구분하는가`
- **리스크 초안**: 검색 근거 없이 그럴듯한 답(환각), 존재하지 않는 조문·판례 인용, 법률 문항에서 틀린 단정의 피해(수험생 오학습), 호출 오류를 "근거 없음"으로 잘못 세기
- **PM 산출물 초안**: P3 답변 상태 흐름(답변 / 근거 부족 / 오류), 인용 INV / P5 REJ(근거 부족, 모델 오류, 검색 실패) / P6 AC(인용 청크 ID·원문 위치가 검색 결과에 존재), NFR(근거 없음 대응 /3)

### U-2 오프라인 평가 실험 (고정 평가셋·재현성)
- **PM 관점**: `평가 무결성 | 개발용·최종용 분리, 최종용 버전 고정, 정답표 누출 경로(색인·프롬프트·리라이터)` / `동일 조건 | A/B/C·최적화 비교에서 고정해야 하는 것(모델·프롬프트·출력 한도·컨텍스트 수)` / `기록 완결성 | 실행마다 남길 필드, 실패·재시도·워밍업·추가 실험 식별`
- **리스크 초안**: 결과를 보고 기준을 바꿈, 최종 평가셋으로 튜닝, 실패 실행 삭제, 청킹 변경 후 근거 매핑이 낡음, 버전이 기록되지 않아 재현 불가
- **PM 산출물 초안**: P3 평가셋 문항·실행 기록 도메인과 버전 INV / P4 마일스톤에 "최종 설정 고정" 시점 / P6 NFR(지표 정의·분모·기록 필드)

### U-3 신뢰할 수 없는 검색 문서 (프롬프트 인젝션)
- **PM 관점**: `문서 속 지시문 | 검색된 문서에 지시문이 있을 때 시스템은 무엇을 하지 않는가`
- **리스크 초안**: 문서 속 지시가 시스템 지시처럼 실행됨, 비밀정보 노출 요청을 따름
- **PM 산출물 초안**: P3 INV(검색 문서는 데이터) / P6 AC(지시문이 든 문서가 검색돼도 지시를 따르지 않음) — 근거 C-11

## 4. 판정 결과로 더해지는 항목 (요약)

| 특성 | 해당으로 보면 더 정하고 만들게 되는 것 |
|---|---|
| TR-06 백그라운드 처리 | 색인 재생성·평가 일괄 실행이 끝났는지, 실패한 건이 어디에 남는지를 정하고 확인하는 기준을 만든다 |
| TR-07 파일·대량 데이터 | 가져올 법령·판례의 양(건수·크기)과 결과 파일의 형식을 정하고, 처리 시간·크기 기준을 둔다 |
| TR-08 외부 연동 | 생성 모델·법령 API가 실패하거나 늦을 때 사용자에게 무엇을 보여 주고 기록에 무엇을 남길지 정한다 |
| TR-09 화면 | 질문·답변·근거·오류를 보는 화면(또는 API 확인 경로)의 구성과 상태별 표시를 정한다 |
| TR-12 성능·캐시 | 응답 시간 측정 조건과 목표값, 캐시를 고르면 캐시가 낡은 답을 내지 않는 기준을 정한다 |
| TR-13 배포·운영 환경 | 다른 환경에서 README만으로 다시 실행되는지 확인하는 기준을 둔다(웹 배포는 선택 범위) |
| 미분류 U-1~U-3 | 근거 인용·근거 부족 안내·실패 구분 규칙, 평가 무결성·기록 규칙, 문서 속 지시문 무시 규칙을 정한다 |

ARCH가 검토할 결정 영역: 일괄 실행 방식과 실패 기록(TR-06), 수집·색인 저장 위치와 크기 제한(TR-07), 외부 API 어댑터 경계·시험용 대역·시간 제한·재시도(TR-08), 화면 기술(TR-09, C-10), 캐시 방식·키·무효화(TR-12, C-07 선택 시), 실행·재현 구성(TR-13).
