# 03. 도메인 정의 (C1)

## 1. 한 문장 정의
2026년 변호사시험 선택형 민사법 문항(지문+보기)을 입력하면, 민법 조문과 민사 판례 요지에서 근거를 검색해 정답 번호와 보기별 근거(출처)를 제시하거나, 근거가 부족하면 정보 부족을 안내하는 수험생용 학습 Knowledge Agent. (REQ-001, C-04, Q-001·Q-002·Q-009 답)

## 2. 액터 & 목표

| 액터 | 목표 | 근거 |
|---|---|---|
| 수험생 | 문항을 넣고 정답 번호와 근거 조문·판례를 확인해 법리를 학습한다. 근거가 없으면 지어낸 답 대신 "정보 부족"을 받는다 | REQ-001, Q-001 답 |
| 개발자·운영 담당(1인 겸임) | 별도 수집한 법령·판례 파일을 가져와 정제·색인하고, 설정·평가셋을 고정하고, 평가 실행·실패 분석·보고서를 만든다 | REQ-039, 070, 079, 프로파일 §4 |
| 채점자(사람) | LLM 1차 채점을 전수 검토해 최종 채점을 확정한다 | REQ-077, Q-006 답 |
| 재현 검증자(별도 에이전트 세션) | 새로 클론한 폴더·새 가상환경에서 README만 보고 색인 재생성과 대표 사례를 재실행한다 | REQ-082, Q-006 답 |
| 시스템: 생성 모델 | 리라이트 질의 생성, 답변 생성, LLM 1차 채점 | C-02, Q-005·Q-006 답 |
| 원문 파일(사용자 별도 수집) | 민법 조문·민사 판례 원문 JSONL 제공, 수집 방법은 `data/MANIFEST.md` | C-04, DOC-03 S2, CR-002 |

## 3. 용어집 (코드 식별자 후보 — 최종 이름은 ARCH가 확정)

| 용어 | 정의 | 클래스·메서드 후보 |
|---|---|---|
| 원문 문서 | 가져온 민법 조문 1개 또는 판례 1건. 종류(조문/판례), 원본 파일·줄, 내용 해시를 가진다 | `SourceDocument` (`kind: STATUTE_ARTICLE \| PRECEDENT`) |
| 청크 | 원문 문서를 나눈 검색 단위. 판례는 판시사항·판결요지 범위만(Q-009). 참조조문은 메타데이터 | `Chunk` |
| 원문 위치 | 청크가 원문의 어디인지(조문: 조·항·호 / 판례: 사건번호·판시사항·판결요지 구분) | `SourceLocation` (형식은 AQ-007) |
| 코퍼스·색인 버전 | 수집 범위·정제·청킹 설정·임베딩 모델로 정해지는 색인 판본 | `IndexVersion`, `Index.rebuild()` |
| 문항 | 수험생 입력. 지문 1개 + 보기 5개 | `ExamItem` (`stem`, `options`) |
| 리라이트 질의 | 문항을 보기별 법률 용어 검색어로 바꾼 것. 원문항과 함께 저장 | `QueryRewriter.rewrite(item) -> list[RewrittenQuery]` |
| 검색 구성 | A(Vector) / B(Hybrid) / C(Hybrid+re-ranking), 리라이트 사용 여부 | `RetrievalConfig`, `RetrievalMode.A/B/C` |
| 후보 | 검색이 돌려준 청크와 점수·재정렬 전후 순위 | `Candidate` |
| 검색 | 질의로 후보를 찾는 일 | `Retriever.search()`, `HybridRetriever.fuse()`, `Reranker.rerank()` |
| 근거 | 답변에 실제 인용한 후보 청크 | `Citation` |
| 답변 | 문항에 대한 결과. 결과 종류(답변/오류), 고른 번호(항상 1~5), 근거 충족 여부, 보기별 판단, 인용 | `Answer` (`outcome: ANSWERED \| ERROR`, `evidence_sufficient: bool`) |
| 답하기 | 문항 → 검색 → 결합 → 재정렬 → 근거 선택 → 답변 | `KnowledgeAgent.answer(item) -> Answer` |
| 평가 문항 | 평가셋의 한 문항. 질문 ID, 구분(dev/test), 유형(직접/변형/근거 없음), 출처(기출/직접 작성), 기대 답(정답 번호+정답 보기 핵심 사실), 허용 근거, 원문 위치, 부재 판정 이유 | `EvalQuestion` |
| 평가셋 | 평가 문항 30개의 판본 | `EvalSet`, `EvalSet.freeze()` |
| 성공 기준 | 우선순위와 목표값. 결과 전에 고정 | `SuccessCriteria`, `SuccessCriteria.freeze()` |
| 실행 | 한 구성으로 평가 문항들을 돌린 묶음. 실행 ID, 구성, 버전들, 실행 종류 | `Run` (`kind: MAIN \| WARMUP \| RETRY \| EXTRA`) |
| 실행 기록 | 실행 안의 문항 1건 결과(후보·점수·순위·원본 답변·출처·시간·상태) | `RunRecord` (`status: OK \| ERROR \| TIMEOUT`) |
| 채점 | 실행 기록 1건의 지표 판정. 판정 주체(LLM/사람)를 구분 | `Grade` (`grader: LLM \| HUMAN`), `Grader.grade(record)` |
| 실패 유형 | 검색 누락 / 순위 실패 / 생성 오류 / 잘못된 인용 / 근거 없음 대응 실패 | `FailureCategory` |

## 4. 도메인 클래스별 규칙

| 클래스 | 생성 시 검증 | 행위가 스스로 검사(위반 시 거부) | 근거 |
|---|---|---|---|
| `Chunk` | 문서 ID·원문 위치·색인 버전이 있다 | — | REQ-026, 044, INV-02 |
| `ExamItem` | 지문이 비어 있지 않다, 보기는 5개 (D-003 R-3: 보기 수가 5가 아니면 입력 오류) | — | Q-001 답 |
| `Answer` | 결과 종류가 정확히 하나 | 답변(ANSWERED)이면 고른 번호와 그 보기의 인용이 1개 이상 있다. 인용은 이 답변의 후보 안에 있다 | INV-01, 03, 13 |
| `QueryRewriter.rewrite` | — | 입력에 정답·허용 근거가 없다. 실패하면 원문항을 질의로 돌려준다 | INV-04, 10, REQ-066, 067 |
| `EvalSet` | 30문항 = dev 10(답변 가능 8·근거 없음 2) + test 20(직접 10·변형 7·근거 없음 3). 근거 없음 문항은 허용 근거가 비어 있고 부재 이유가 있다 | `freeze()` 뒤에는 문항·정답을 바꾸지 않는다. 근거 매핑 갱신은 최종 평가 실행 전에만, 재고정 기록과 함께 | INV-05, 06, 12, REQ-041~048 |
| `SuccessCriteria` | 우선순위와 지표별 목표값이 모두 있다 | 최종 평가 첫 실행 뒤에는 바꾸지 않는다 | INV-06, REQ-037 |
| `Run` | 구성·버전(문서/색인/모델/프롬프트)·실행 종류가 있다 | test 문항은 `MAIN`·`RETRY`·`EXTRA` 최종 평가 실행에서만 쓴다(개발·튜닝 실행 금지) | INV-05, 07, 11 |
| `Grade` | 판정 주체가 있다 | 호출 오류 기록을 "근거 없음 대응 성공"으로 채점하지 않는다 | REQ-074, INV-03 |

## 6. 불변 규칙 (Invariants)

- INV-01 답변이 인용한 모든 청크는 그 실행의 검색 후보 안에 있다. (REQ-058, 073)
- INV-02 모든 청크는 문서 ID, 원문 위치, 색인 버전을 가진다. (REQ-026, 044)
- INV-03 답변 결과는 답변 / 오류 중 정확히 하나다. 검색 실패·모델 오류를 답변으로 기록하지 않는다. (REQ-059, 074, CR-014)
- INV-04 정답표·기대 답·허용 근거는 색인, 생성 프롬프트, 리라이터 입력에 들어가지 않는다. (REQ-047, 066, C-09)
- INV-05 최종 평가용(test) 문항은 개발·튜닝 실행에 쓰이지 않는다. (REQ-046)
- INV-06 고정된 성공 기준·평가셋·최종 설정은 최종 평가 첫 실행 뒤 바뀌지 않는다. 바꾼 실험은 추가 실험(`EXTRA`)으로 분리한다. (REQ-037, 046, 078)
- INV-07 본 평가 기록은 삭제하지 않는다. 워밍업·재시도·추가 실험은 본 평가와 구분 표시된다. (REQ-078, 091, 100)
- INV-08 A/B/C와 C+리라이트 비교는 같은 생성 모델·프롬프트·출력 한도·컨텍스트 제한을 쓴다. 바뀌는 것은 검색 구성과 리라이트 사용 여부뿐이다. (REQ-055, C-02)
- INV-09 검색 문서 속 지시문은 데이터이며 시스템의 동작·권한을 바꾸지 않는다. (REQ-099, C-11)
- INV-10 리라이트가 실패하면 원문항으로 검색하며, 리라이트 실패만으로 답변이 오류가 되지 않는다. (REQ-067)
- INV-11 모든 실행 기록은 문서/색인/모델/프롬프트 버전과 실행 ID·질문 ID·구성을 가진다. (REQ-076)
- INV-12 평가셋은 30 = dev 10(답변 가능 8·근거 없음 2) + test 20(직접 10·변형 7·근거 없음 3)이며 질문 ID로 분리된다. (REQ-041~043)
- INV-13 답변 결과는 **항상** 정답 번호 1~5를 포함한다. `evidence_sufficient=true`이면 고른 보기의 근거 인용이 1개 이상이어야 한다. `false`이면 인용이 없어도 되며 추정임을 안내한다. (REQ-031, 054, Q-007 답, CR-014)

## 7. D-003 확정 규칙 (APPROVED by user, 2026-11-23)

- R-1 본 평가는 첫 시도를 기록한다. 오류·timeout 건은 그대로 0점·오류로 세고, 재시도는 `RETRY`로 따로 기록해 본 지표에 섞지 않는다. (ASM-005)
- R-2 일부 보기만 근거가 있고 정답 판단에 필요한 보기의 근거가 없으면, **번호는 고르되** `evidence_sufficient=false`로 표시하고 추정임을 안내한다. 근거가 있는 보기의 판단은 참고로 함께 보여 준다. (INV-13, Q-008 답 A, CR-014)
- R-3 입력 문항의 보기 수가 5가 아니거나 지문이 비면 입력 오류로 거부한다. (ExamItem)
- R-4 수험생 화면에는 학습용 결과이며 법률 자문이 아님을 한 줄 안내한다. (C-12 "서비스 수준 주장 금지"의 화면 반영, D-003 승인)
