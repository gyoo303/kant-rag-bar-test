# 07. 화면 구성 (C1)

> 화면 기술(Streamlit / 웹·API)은 ARCH가 정한다(C-10, AQ-002). API를 고르면 SCR-01은 API 요청·응답과 그 확인 경로(API 문서 화면 또는 호출 예시)로 바뀐다. 시각 디자인은 정하지 않는다.

## 1. 화면 목록

| SCR | 이름 | 경로 후보 | 액터 | 관련 US | 마일스톤 |
|---|---|---|---|---|---|
| SCR-01 | 문항 풀이 | `/` | 수험생 | US-09, US-10, US-11 | M3 |

운영 스토리(US-01~08, 12~17)는 화면이 아니라 확인 경로(명령·파일)로 확인한다(08-traceability §1).

## 2. SCR-01 문항 풀이 — 텍스트 와이어프레임

```
┌ SCR-01 문항 풀이 ─────────────────────────────────────┐
│ 학습용 결과이며 법률 자문이 아닙니다.          ← R-4    │
│ [지문 입력 칸]                                  ← REQ-001│
│ [보기 ① ~ ⑤ 입력 칸 5개]                        ← R-3    │
│ [제출]                                                    │
├ 결과 ───────────────────────────────────────────────────┤
│ 결과 종류: 성공 / 근거 부족 / 입력 오류 / 검색 실패 / 모델 오류 │
│ (성공) 정답: ③                                  ← Q-007  │
│ 보기별 판단 표: 보기 | 옳음·틀림·근거 부족 | 이유 | 인용 │
│ 인용 목록: 청크 ID | 원문 위치(민법 제○조 / 대법원 ○○다○○) | 출처 링크 │ ← REQ-058
│ (접힘) 검색 정보: 구성(A/B/C), 리라이트 질의, 소요 시간  │ ← REQ-065
└───────────────────────────────────────────────────────┘
```

## 3. 필수 표시 요소

| 요소 | 내용 | 근거 |
|---|---|---|
| 학습용 안내 | 항상 한 줄 | R-4, AC-11-2 |
| 입력 | 지문 1, 보기 5 | Q-001, R-3 |
| 결과 종류 | 5종 중 하나를 글자로 표시 | INV-03 |
| 정답 번호 | 성공일 때만 | INV-13 |
| 보기별 판단 | 보기 5개 각각 판단과 이유 | US-09 |
| 인용 | 청크 ID, 원문 위치, 출처 링크 | REQ-058, AC-09-1 |
| 검색 정보 | 구성, 리라이트 질의(또는 fallback 표시), 소요 시간 | REQ-065, REQ-075 |

## 4. 상태별 표시

| 상태 | 표시 |
|---|---|
| 처리 중 | 처리 중 표시, 제출 버튼 비활성 |
| 성공 | 정답 번호, 보기별 판단, 인용 목록 |
| 근거 부족 | "정보 부족" 안내, 정답 번호 없음. 근거 있는 보기의 판단은 "참고"로 표시 가능(R-2) |
| 입력 오류 | 잘못된 부분(지문 없음 / 보기 수) 안내, 결과 영역에 다른 내용 없음 |
| 검색 실패 | "검색 오류" 안내 — 근거 부족 안내와 다른 문구 |
| 모델 오류 | "답변 생성 오류" 안내 — 근거 부족 안내와 다른 문구 |

## 5. 공통 요소
- 학습용 안내 줄, 결과 종류 표시, 인용 목록 행(청크 ID·원문 위치·출처 링크)은 다른 화면이 생겨도 같은 형식으로 쓴다.

## 6. 시연 흐름 초안 (프로파일 §7: 정상·근거 없음·최적화 시연)
1. 정상: test의 직접 검색 문항 1개 → 정답 번호·인용 확인 → 인용 원문 위치를 법령 원문과 대조.
2. 근거 없음: 상법 문항 1개 → "정보 부족" 안내, 번호 없음.
3. 최적화: 표현 변형 문항 1개를 리라이트 끔/켬으로 비교 → 리라이트 질의와 인용 차이.
4. 오류 구분: 입력 오류(보기 4개) → 입력 오류 표시.
5. 결과: report.md 비교표와 실패 사례 1개.
