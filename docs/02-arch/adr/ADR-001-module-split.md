# ADR-001: 기능 모듈 분할과 모듈 간 참조
- 상태: Accepted (user, 2026-11-23) — 옵션 B
- 관련 계층: [어플리케이션] [레이어]
- 근거: DRV-C-01, DRV-C-05, DRV-C-08, RISK-15, RISK-16, INV-04, INV-08, 03-domain §3

## 맥락
기능은 크게 네 덩어리다: 원문 수집·청킹·색인(US-05), 검색 A/B/C·리라이트(US-06~08, 10), 근거 기반 답변(US-09), 평가 실행·채점·지표(US-04, 12~15). 1인 5일 일정이라 구조가 과하면 안 되지만, 규칙(INV)을 LangChain·외부 API 없이 시험할 수 있어야 하고(RISK-15), 평가 데이터가 검색·생성 쪽으로 새지 않아야 한다(RISK-01).

## 검토한 옵션
| 옵션 | 장점 | 단점 | AI 부채 영향(D2~D4) | 외부 기준 영향 | 되돌리기 비용 |
|---|---|---|---|---|---|
| A. 스크립트 몇 개(수집·검색·평가) + 공용 함수 | 가장 빠름 | 규칙과 외부 호출이 섞여 단위 시험 어려움, 정답 누출 경로를 구조로 막지 못함 | 높음 | CRT-08·10 증빙 약함 | 중 |
| B. 패키지 1개 + 기능 모듈 4개(`corpus`, `retrieval`, `answering`, `evaluation`), 각 모듈은 `domain`/`application`/`infrastructure` 3계층, 진입점은 `entrypoints` 1곳 | 규칙 시험 쉬움, 평가 모듈만 정답 데이터를 읽게 구조로 막음 | 파일 수가 늘어남 | 낮음 | CRT-03~08 증빙이 모듈별로 분명 | 중 |
| C. 모듈마다 별도 패키지·별도 설치 | 경계가 가장 강함 | 1인 5일에 과함 | 중(과설계) | 차이 없음 | 높음 |

## 계층 관점 설명
- 패키지 `src/lawqa/` 아래 `corpus`, `retrieval`, `answering`, `evaluation` 모듈과 공용 `shared`(설정·시간·버전 등 순수 값), 진입점 `entrypoints`(명령줄 + 화면).
- 모듈 안 의존: `application → domain`, `infrastructure → domain`(도메인의 저장소·외부 호출 계약을 구현). `domain`은 표준 라이브러리만 쓴다.
- 모듈 간 의존(한 방향): `evaluation → answering → retrieval → corpus`. 다른 모듈은 상대의 **application 서비스와 domain 타입만** 쓴다(상대 infrastructure import 금지). 거꾸로 가는 의존은 없다.
- **`evaluation`만 평가셋·정답을 읽는다.** `answering`·`retrieval`은 `evaluation`을 import할 수 없으므로 정답이 검색·생성 입력에 들어갈 경로가 구조상 없다(INV-04).

## 결정
결정: B — 규칙 시험과 정답 누출 차단을 구조로 해결하면서 패키지 하나로 단순하게 유지한다.

## 결과
- 좋아지는 점: INV 단위 시험, 모듈별 증빙, 정답 누출 경로 차단
- 감수할 점: 계층 파일이 늘어남(모듈당 3~4개 파일)
- 후속 작업: A6 디렉토리 트리, GATE 계층 격리·누출 검사

## 쉬운 설명
- A. 스크립트 몇 개: 무엇이 달라지나 — 파일 몇 개로 바로 만든다. / 좋은 점 — 가장 빠르다. / 감수할 점 — 규칙 시험이 어렵고, 정답이 검색 쪽으로 새는 실수를 구조로 막지 못한다. / 나중에 바꾸기: 보통.
- B. 패키지 하나 + 기능 4개로 나누기: 무엇이 달라지나 — 수집·검색·답변·평가를 폴더로 나누고, 각 폴더 안에서 "규칙 / 흐름 / 외부 연결"을 나눈다. / 좋은 점 — 규칙을 따로 시험할 수 있고, 평가 폴더만 정답을 읽게 해 누출을 막는다. / 감수할 점 — 파일 수가 늘어난다. / 나중에 바꾸기: 보통.
- C. 기능마다 별도 패키지: 무엇이 달라지나 — 기능마다 따로 설치한다. / 좋은 점 — 경계가 가장 강하다. / 감수할 점 — 1인 5일에 과하다. / 나중에 바꾸기: 어려움.
- 추천: B — 평가 공정성(정답 누출 방지)을 구조로 지키면서도 과하지 않다.
