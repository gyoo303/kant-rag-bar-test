# ADR-003: 설정·비밀값 관리
- 상태: Accepted (user, 2026-11-23) — 옵션 B
- 관련 계층: [인프라]
- 근거: DRV-C-11, RISK-08, RISK-09, NFR-08, C-11, AQ-010

## 맥락
비밀값은 OpenAI API 키와 법령 OPEN API 인증 값(OC) 두 개다. 그 밖의 설정(모델 이름, 검색 후보 수, k, 시간 제한 등)은 **실행 기록에 버전으로 남겨야** 하므로(INV-11) 비밀값과 따로 관리하고 저장소에 커밋해야 한다.

## 검토한 옵션
| 옵션 | 장점 | 단점 | AI 부채 영향 | 외부 기준 영향 | 되돌리기 비용 |
|---|---|---|---|---|---|
| A. `os.environ`만 사용, 실험 설정도 환경변수 | 의존성 없음 | 실험 설정이 커밋되지 않아 재현 불가 | 높음(RISK-09) | CRT-11 위험 | 낮음 |
| B. 비밀값은 `.env` + `python-dotenv`, 실험 설정은 저장소의 TOML 파일(`config/*.toml`, 표준 `tomllib`로 읽음), 설정 객체는 표준 `dataclass` | 비밀값과 실험 설정 분리, 실험 설정 파일 해시를 버전으로 기록 가능, 의존성 1개 | 값 검증을 직접 써야 함 | 낮음 | CRT-10·11 충족 | 낮음 |
| C. B와 같되 `pydantic-settings`로 검증 | 타입 검증 자동 | 의존성 2개 추가(pydantic, pydantic-settings) | 낮음 | 같음 | 낮음 |

## 계층 관점 설명
- `.env`(커밋 안 함): `OPENAI_API_KEY`, `DATABASE_URL`(로컬 Docker DB 접속 문자열). `.env.example`(커밋): 이름과 용도만.
- `config/base.toml`(커밋): 모델 이름, 임베딩·reranker 이름, 후보 수, k, 시간 제한, 경로. 구성별 차이는 `config/` 안 구성 파일로 둔다(A4에서 확정).
- `src/lawqa/shared/settings.py`가 두 곳을 읽어 불변 설정 객체를 만들고, 설정 파일 내용 해시를 `config_version`으로 실행 기록에 남긴다.
- 비밀값은 로그·실행 기록·화면에 쓰지 않는다.

## 결정
결정: B — 비밀값과 실험 설정을 나눠 재현성을 지키고, 의존성은 `python-dotenv` 하나로 끝낸다.

## 결과
- 좋아지는 점: 설정 버전이 실행 기록에 남음, 비밀값 커밋 경로 차단
- 감수할 점: 설정 값 검증 코드를 직접 쓴다(필수 키·범위 몇 개)
- 후속 작업: TKT-BE(설정 모듈), GATE 비밀값

## 쉬운 설명
- A. 환경변수만: 무엇이 달라지나 — 모든 값을 컴퓨터 환경변수로 넣는다. / 좋은 점 — 추가 설치가 없다. / 감수할 점 — 실험 설정이 저장소에 안 남아 나중에 같은 조건으로 다시 돌리기 어렵다. / 나중에 바꾸기: 쉬움.
- B. 비밀값은 `.env`, 실험 설정은 저장소 파일: 무엇이 달라지나 — 키는 커밋하지 않는 파일에, 후보 수·모델 이름 같은 실험 값은 커밋하는 설정 파일에 둔다. / 좋은 점 — 어떤 설정으로 돌렸는지 기록이 남는다. / 감수할 점 — 값 확인 코드를 조금 직접 쓴다. / 나중에 바꾸기: 쉬움.
- C. B + 자동 검증 라이브러리: 무엇이 달라지나 — 값 검증을 라이브러리가 한다. / 좋은 점 — 잘못된 값을 자동으로 잡는다. / 감수할 점 — 설치할 것이 두 개 늘어난다. / 나중에 바꾸기: 쉬움.
- 추천: B — 재현성과 비밀 보호를 가장 적은 설치로 해결한다.
