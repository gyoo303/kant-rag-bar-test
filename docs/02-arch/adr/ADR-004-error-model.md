# ADR-004: 오류 형식 (결과 종류와 오류 변환 위치)
- 상태: Accepted (user, 2026-11-23) — 옵션 B
- 관련 계층: [레이어] [모듈 협력 구조]
- 근거: INV-03, REJ-01~06, AC-09-3~6, AC-11-3, AC-14-3, RISK-06, RISK-18, U-1

## 맥락
PM AC의 결과 종류는 성공 / 입력 오류 / 검색 실패 / 모델 오류 / 거부(규칙 위반) 다섯 가지다(CR-014로 '근거 부족'은 결과 종류가 아니라 성공의 속성 `evidence_sufficient`가 됐다). 같은 결과가 화면, 명령줄 일괄 실행, 실행 기록에 똑같이 나와야 하고, 특히 오류가 "근거 부족"으로 섞이면 지표가 틀어진다(RISK-06). 실행 인터페이스가 HTTP가 아닐 수 있으므로(ADR-012) 응답 코드보다 **결과 객체 하나**가 기준이어야 한다.

## 검토한 옵션
| 옵션 | 장점 | 단점 | AI 부채 영향 | 외부 기준 영향 | 되돌리기 비용 |
|---|---|---|---|---|---|
| A. 예외를 그대로 위로 던지고 화면·일괄 실행이 각각 잡아 표시 | 코드가 짧음 | 화면과 일괄 실행의 분류가 달라질 수 있음, 기록에 남기 전 실행이 멈춤 | 높음(RISK-06·18) | CRT-06·16 위험 | 낮음 |
| B. `answering` 응용 서비스가 모든 예외를 결과 객체 `Answer`(결과 종류 + 오류 코드 + 사용자 문구)로 바꿔 돌려주고, 화면·일괄 실행·기록은 이 객체만 쓴다 | 분류가 한 곳, 일괄 실행이 멈추지 않음, 기록에 오류 종류가 남음 | 결과 객체 필드가 늘어남 | 낮음 | CRT-06·16·18 증빙 | 중 |

## 계층 관점 설명
- 도메인 예외(`domain/errors.py`): `InvalidExamItemError`(입력 오류), `RuleViolationError`(거부: test 문항 개발 사용, 고정 후 변경, 정답 누출).
- 외부 오류(`infrastructure`): 어댑터가 라이브러리 예외를 `RetrievalFailedError`, `ModelCallError`, `ModelTimeoutError`, `ModelOutputFormatError`로 바꾼다(라이브러리 예외가 위로 새지 않음).
- 변환 위치 하나: `AnswerService.answer()`가 위 예외를 잡아 `Answer(outcome=..., error_code=..., user_message=...)`로 바꾼다. 그 밖의 예상하지 못한 예외도 `outcome=ERROR, error_code=UNEXPECTED`로 바꾸고 로그에 남긴다(빈 except 금지와 충돌하지 않게 로그 필수).
- 일괄 실행에서는 오류 결과도 그대로 기록하고 다음 문항으로 진행한다(R-1).
- 결과 종류 ↔ 표시 대응표와 오류 코드 목록은 A4 에러 모델에 둔다. HTTP 응답 코드는 ADR-012가 API를 고를 때만 A4에 추가한다.

## 결정
결정: B — 화면·일괄 실행·기록이 같은 분류를 쓰게 해 "오류를 근거 부족으로 세는" 실수를 구조로 막는다.

## 결과
- 좋아지는 점: 결과 분류 일관, 일괄 실행 중단 방지
- 감수할 점: 오류 코드 목록 관리
- 후속 작업: A4 에러 모델, TKT-BE(answering 서비스)

## 쉬운 설명
- A. 오류를 그대로 던지기: 무엇이 달라지나 — 오류가 나면 화면이나 평가 실행이 각자 알아서 처리한다. / 좋은 점 — 코드가 짧다. / 감수할 점 — 같은 오류를 곳마다 다르게 분류하거나, 평가 실행이 중간에 멈출 수 있다. / 나중에 바꾸기: 쉬움.
- B. 결과 하나로 모으기: 무엇이 달라지나 — 답변 기능이 성공·근거 부족·오류를 모두 "결과" 하나에 담아 돌려준다. / 좋은 점 — 화면·평가·기록이 같은 분류를 쓰고, 오류가 나도 평가가 다음 문항으로 넘어간다. / 감수할 점 — 오류 종류 목록을 관리해야 한다. / 나중에 바꾸기: 보통.
- 추천: B — 오류를 "근거 부족"으로 잘못 세면 평가 지표가 틀어지기 때문이다.

## 개정
- 2026-11-24 (CR-014·016): 결과 종류에서 '근거 부족'을 뺐다. RISK-06은 "호출 오류를 근거 부족으로 집계"에서 "호출 오류를 답변으로 집계"로 바뀐다. 오류와 답변을 섞지 않는다는 취지는 그대로다.
