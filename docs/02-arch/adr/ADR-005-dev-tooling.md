# ADR-005: 개발 도구·환경
- 상태: Accepted (user, 2026-11-23) — 옵션 B
- 관련 계층: [인프라]
- 근거: DRV-C-14, NFR-04, RISK-09, C-13(잠금 파일), US-16

## 맥락
다른 환경(별도 세션의 새 클론)에서 README만으로 재현해야 한다(NFR-04). 현재 개발 PC(Windows 11, RTX 5060 Laptop 8GB)에는 Python이 설치되어 있지 않다. 주요 패키지(langchain 1.5.x, streamlit 1.67)는 Python 3.11 이상을 요구하고 3.12는 모두 지원한다(조사 2026-11-23, PyPI 메타데이터).

## 계층 관점 설명
- Python 3.12 고정(`pyproject.toml`의 `requires-python = ">=3.12,<3.13"`, `.python-version`).
- 명령: `uv sync`(설치) → `uv run pytest` → `uv run ruff check .` → `uv run ruff format --check .`.
- 코어 패키지는 `pyproject.toml`에 상한 없이 최소 버전만 쓰고, 실제 버전은 `uv.lock`이 고정한다. 코어 버전 변경은 ADR 대상.
- 테스트 저장소: 단위 시험은 저장소 없이, 저장 계층 시험은 Docker PostgreSQL의 `lawqa_test` 데이터베이스(ADR-006), 외부 API는 시험용 대역(가짜 어댑터)으로 대신한다. 로컬 DB는 `docker compose up -d db`로 띄운다.
- 타입 검사 도구는 쓰지 않는다(옵션 C 기각: 일정).

## 결정
결정: B — 이 PC에 Python이 없는 상황에서 설치부터 잠금까지 명령 몇 개로 재현된다.

## 결과
- 좋아지는 점: README 재현 명령이 짧고 정확함
- 감수할 점: `uv` 설치 한 번(공식 설치 스크립트)
- 후속 작업: TKT-BE(프로젝트 골격), A7 GATE 명령

## 쉬운 설명
- A. 일반 Python 설치 + requirements: 무엇이 달라지나 — Python을 따로 설치하고 패키지 목록 파일로 설치한다. / 좋은 점 — 가장 흔한 방식이다. / 감수할 점 — 다른 컴퓨터에서 하위 패키지 버전이 달라질 수 있다. / 나중에 바꾸기: 쉬움.
- B. uv 하나로 관리: 무엇이 달라지나 — Python 설치, 가상환경, 패키지 버전 고정을 도구 하나로 한다. / 좋은 점 — 다른 환경에서도 명령 두세 줄로 똑같이 설치된다. / 감수할 점 — 처음 한 번 uv를 설치하고 익혀야 한다. / 나중에 바꾸기: 쉬움.
- C. B + 타입 검사: 무엇이 달라지나 — 코드 타입 오류도 자동 검사한다. / 좋은 점 — 버그를 일찍 잡는다. / 감수할 점 — 5일 일정에 설정·수정 시간이 든다. / 나중에 바꾸기: 쉬움.
- 추천: B — 재현성이 평가 항목이고, 지금 PC에 Python이 없기 때문이다.
