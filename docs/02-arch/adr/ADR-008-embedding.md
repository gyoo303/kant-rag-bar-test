# ADR-008: 임베딩 모델
- 상태: Accepted (user, 2026-11-23) — 옵션 A(text-embedding-3-small)
- 관련 계층: [인프라]
- 근거: C-03, AQ-001, RISK-04, DRV-Q-02, DRV-Q-04, D-007

## 맥락 (조사 2026-11-23)
색인 규모는 판례 4만 건(판시사항+판결요지 약 400토큰 가정) + 민법 조문 약 1,200개 ≈ 1,620만 토큰. 품질 우선(D-007), 2일차 안에 색인 완료(DRV-Q-04).
- OpenAI `text-embedding-3-small`: $0.02/1M(약 $0.32), 1536차원
- OpenAI `text-embedding-3-large`: $0.13/1M(약 $2.11), 3072차원(`dimensions`로 축소 가능)
- `BAAI/bge-m3`(로컬, MIT): 1024차원, 가중치 약 2.3GB, 이 PC GPU(RTX 5060 8GB)에서 실행 가능하나 처리 속도 미확인

## 검토한 옵션
| 옵션 | 장점 | 단점 | AI 부채 영향 | 외부 기준 영향 | 되돌리기 비용 |
|---|---|---|---|---|---|
| A. `text-embedding-3-small` | 가장 쌈, 설정 간단 | 다국어·법률 문장 품질이 large보다 낮음 | 낮음 | 중립 | 중(재색인) |
| B. `text-embedding-3-large`, `dimensions=1536` | 품질 우선 원칙에 맞음, 비용 약 $2, 저장 공간은 small과 같음 | 외부 호출 시간(배치 호출로 수십 분 예상, 미확인) | 낮음 | 중립 | 중(재색인) |
| C. `bge-m3` 로컬 GPU | API 비용 0, 외부 전송 없음 | PyTorch·CUDA 설치 부담, 4만 건 처리 시간 미확인 → 2일차 위험 | 중 | 중립 | 중 |

## 결정
결정: A — `text-embedding-3-small`, 1536차원(사용자 선택). 임베딩 모델 이름·차원은 색인 버전에 들어간다(INV-11).

## 결과
- 좋아지는 점: 수집 직후 바로 색인, 설치 부담 없음
- 감수할 점: 법령 데이터를 OpenAI로 보냄(공공데이터, ASM-010) — `docs/problem.md` 데이터 이용 조건에 적는다
- 후속 작업: TKT-BE(색인기)

## 쉬운 설명
- A. 작은 OpenAI 모델: 무엇이 달라지나 — 문장을 숫자로 바꾸는 데 가장 싼 모델을 쓴다. / 좋은 점 — 약 $0.3로 끝난다. / 감수할 점 — 법률 문장 검색 품질이 조금 낮을 수 있다. / 나중에 바꾸기: 보통(색인을 다시 만든다).
- B. 큰 OpenAI 모델(크기 줄여 저장): 무엇이 달라지나 — 더 좋은 모델을 쓰고 저장 크기는 작은 모델과 같게 줄인다. / 좋은 점 — 약 $2로 품질을 높인다. / 감수할 점 — 법령 데이터가 OpenAI로 전송된다(공개 자료라 문제는 작다). / 나중에 바꾸기: 보통.
- C. 내 컴퓨터 GPU 모델: 무엇이 달라지나 — 노트북 GPU로 직접 계산한다. / 좋은 점 — 비용이 없고 외부로 보내지 않는다. / 감수할 점 — 설치가 복잡하고 4만 건 처리 시간을 몰라 2일차 일정이 위험하다. / 나중에 바꾸기: 보통.
- 추천: B — 몇 달러 차이로 품질을 높이고 일정 위험이 가장 적다.
