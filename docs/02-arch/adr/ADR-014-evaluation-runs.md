# ADR-014: 평가 실행·채점·고정 기록
- 상태: Accepted (user, 2026-11-23) — 추천안
- 관련 계층: [모듈 협력 구조] [인프라]
- 근거: AQ-011, AQ-012, TR-06, U-2, D-006, R-1, INV-04~07, INV-11, RISK-02, RISK-09, RISK-13, REQ-070~078, REQ-091

## 맥락
본 평가 80건(A/B/C 60 + C+리라이트 20)을 일괄 실행하고, 건마다 원본을 남기고, LLM 1차 채점 + 사람 검토를 분리해 기록해야 한다(D-006). test 문항은 개발 실행에 쓰면 안 되고(INV-05), 고정 뒤 설정을 바꾼 본 평가는 거부해야 한다(INV-06). 실행이 중간에 멈춰도 기록은 남아야 한다(TR-06).

## 검토한 옵션
| 옵션 | 장점 | 단점 | AI 부채 영향 | 외부 기준 영향 | 되돌리기 비용 |
|---|---|---|---|---|---|
| A. 노트북에서 손으로 돌리고 결과를 표로 정리 | 빠름 | 실행 종류·버전·재시도 구분을 사람이 기억, 재현 불가 | 높음 | CRT-08·17 위험 | 낮음 |
| B. 명령줄 일괄 실행기: `python -m lawqa eval run --split test --config C --kind main`. 실행 전 검사(분할·종류·고정 일치) → 건마다 즉시 JSONL에 한 줄 추가(append, 멈춰도 남음) → `--resume`은 같은 run_id에서 기록 없는 문항만 실행. 채점은 `eval grade`(LLM)와 `eval review`(사람 판정 CSV 가져오기)로 분리, 지표는 `eval metrics` | 무결성 규칙을 코드로 검사, 재시작 안전, 판정 분리 | 명령 몇 개 구현 | 낮음 | CRT-08·17·18 증빙 | 중 |

## 계층 관점 설명
- **고정 기록(AQ-012)**: `eval/FREEZE.json`(커밋)에 `success_criteria_sha`, `evalset_sha`(dev/test 파일 해시), `config_sha`, `prompt_sha`, `index_version`, `frozen_at`, git 커밋 해시를 적는다. `eval freeze` 명령이 만들고 git 태그 `freeze-criteria`(M1), `freeze-final`(M3)을 사람이 단다.
- **실행 전 검사**: `kind=main|retry`이면 현재 해시가 `FREEZE.json`과 같아야 함(다르면 `RuleViolationError`, `extra`로만 실행). `split=test`는 `kind ∈ {main, retry, extra}`만 허용(INV-05). `warmup`은 dev 문항만.
- **채점**: LLM 판정은 생성 모델과 같은 `gpt-6-luna`(C-02, 별도 판정 프롬프트·버전 기록). 사람 판정은 `results/<run_id>/review.csv`(LLM 판정 옆에 사람 칸)로 받는다. 지표는 사람 판정 기준으로 계산하고 LLM 판정 일치율을 함께 보고한다.
- **기록 형식(AQ-011)**: A3 실행 기록 스키마.

## 결정
결정: B — 평가 규칙(분할·고정·재시도 분리)을 코드로 강제하고, 멈춰도 기록이 남는다.

## 결과
- 좋아지는 점: CRT-08·17·18 증빙이 파일로 남음, 재실행 안전
- 감수할 점: 명령 4~5개 구현
- 후속 작업: A3 스키마, A5 SEQ, TKT-BE(evaluation)

## 쉬운 설명
- A. 손으로 돌리기: 무엇이 달라지나 — 노트북에서 한 건씩 돌리고 표로 정리한다. / 좋은 점 — 빨리 시작한다. / 감수할 점 — 어떤 설정으로 돌렸는지, 재시도인지를 사람이 기억해야 해서 공정성 증명이 어렵다. / 나중에 바꾸기: 쉬움.
- B. 명령 하나로 일괄 실행: 무엇이 달라지나 — 명령 하나로 80건을 돌리고, 돌리기 전에 "고정한 설정과 같은지, 시험용 문항을 개발에 쓰지 않는지"를 자동 검사한다. 한 건 끝날 때마다 바로 기록하고, 멈추면 이어서 돌린다. / 좋은 점 — 공정성 규칙을 코드가 지키고 기록이 빠짐없이 남는다. / 감수할 점 — 명령 몇 개를 만들어야 한다. / 나중에 바꾸기: 보통.
- 추천: B — 이 과제의 평가 핵심이 "공정하고 재현 가능한 비교"이기 때문이다.
