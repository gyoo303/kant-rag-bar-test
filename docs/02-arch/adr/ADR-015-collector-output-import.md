# ADR-015: 원문 가져오기 — `law_collector` 출력을 그대로 읽기
- 상태: Accepted (user, 2026-11-23) — 옵션 A, 판례 범위는 데이터출처 "대법원"의 민사 판례 전부(하급심 판결 포함)
- 대체: ADR-007 (Superseded by ADR-015)
- 관련 계층: [인프라] [모듈 협력 구조]
- 근거: ADR-007, CR-002~006, TR-07, Q-002·Q-008·Q-009 답, REQ-004, REQ-093, RISK-03

## 맥락
판례·민법 원문은 파이프라인 밖에서 준비한다(사용자 확인 2026-11-23).
- 판례: `law_collector/collect.py fetch --source 대법원`이 받은 `law_collector/data/prec/{판례정보일련번호}.json` — 판례 1건 = 파일 1개, 법령 API `PrecService` 응답 그대로. 실제 수집분 9,984건 전수 확인(2026-11-23): 15개 키 모두 존재, `사건종류명` 전부 "민사", `선고일자` 전부 `YYYYMMDD`, HTML 태그는 `<br/>`뿐, 파일 이름 = `판례정보일련번호`. **`법원명`은 대법원 70%, 고등·지방법원 30%** — 데이터출처 "대법원"에는 하급심 판결도 들어 있다.
- 민법: 법제처에서 내려받은 일반 텍스트 `law_collector/data/law/민법.txt`(UTF-8, BOM 없음, 2,577줄). 수집기 `laws` 명령의 JSON 출력이 아니다. 샘플을 저장소에 커밋해 두었다(법령 본문은 저작권 보호 대상 아님).

## 결정 (A)

### 입력
- 설정 `[paths] raw_dir = "law_collector/data"`. 판례 `raw_dir/prec/*.json`, 민법 `raw_dir/law/민법.txt`.
- **`law/` 안의 `민법.txt` 외 파일은 읽지 않는다**(Q-002 범위, Q-008 근거 없음 문항 보호). 무시한 파일 이름은 가져오기 보고에 "범위 밖 파일 무시"로 적는다.

### 판례
- **선별**: `사건종류명 == "민사"`인 파일 전부. 데이터출처는 수집 단계(`--source 대법원`)에서 정해지므로 `법원명`으로 거르지 않는다(사용자 결정: 하급심 판결 포함). 민사가 아니면 `ImportIssue(OUT_OF_SCOPE)`.
- **필드 매핑**: `판례정보일련번호` → `doc_id = "prec:<값>"`, `사건명` → `title`(없으면 `사건번호`), `사건번호`, `법원명` → `court`, `사건종류명` → `case_type`, `판시사항` → `holdings`, `판결요지` → `summary`, `참조조문` → `referenced_articles`. `판례내용`·`참조판례`는 저장하지 않는다(Q-009).
- **날짜**: `선고일자`는 숫자만 남겨 8자리면 날짜, 아니면 `BAD_DATE`(실제 파일은 모두 `YYYYMMDD`).
- **빈 본문**: 정제 후 `판시사항`·`판결요지`가 둘 다 비면 `ImportIssue(EMPTY_CONTENT)`(실제 수집분의 12%). **사람이 수집 완료 뒤 이런 파일을 일괄 삭제한다**(HANDOFF §3 작업 필요 사항). 삭제 후 가져오기에서 `EMPTY_CONTENT`가 나오면 색인은 "불완전"(REJ-06)으로 남아 본 평가 전 고정(`eval freeze --stage final`)이 막힌다 — 삭제가 끝났는지 확인하는 장치다.
- `source_file = "prec/<파일명>"`, `source_line = 1`.

### 민법 텍스트 파서 (`SourceDocument.statute_articles_from_text`, 순수 함수)
줄마다 앞뒤 공백·BOM·`\r` 제거 후 아래 순서로 판정한다.
| 판정 | 정규식(파이썬) | 처리 |
|---|---|---|
| 편·장·절·관 제목 | `^제\d+(?:편\|장\|절\|관)(?:의\d+)?\s` | 조문 아님. 현재 조문을 닫는다 |
| 특수 제목 | `^제\d+항\s+\S` 이고 **다음 비어 있지 않은 줄이 조 머리** | 조문 아님(예: `제1항 협의상 파양`, `제2항 재판상 파양`). 현재 조문을 닫는다. 본문의 항은 `①` 표시를 쓰므로 줄 머리 `제N항`은 이 두 줄뿐(2026-11-23 파일 확인) |
| 조 머리 | `^제(\d+)조(?:의(\d+))?\s*(?:\((?P<t1>[^)]*)\)\|\[(?P<t2>.*?)\](?=\S\|$))?\s*(?P<rest>.*)$` (표 안이라 `\|`는 정규식의 `|`) | 새 조문 시작. 제목 = t1 또는 t2(대괄호 제목 안의 괄호 허용), `rest`는 본문 첫 줄 |
| 삭제 조문 | 조 머리이고 `rest`가 `삭제`로 시작 | 조문을 만들지 않는다(오류 아님, 보고에 "삭제 조문 N개") |
| 삭제 호 | `^\d+(?:의\d+)?\.\s*삭제` | 그 줄을 버린다 |
| 그 밖의 줄(항 `①…`, 호 `1.`·`1의2.`, 이어지는 문장) | — | 현재 조문 본문에 줄바꿈으로 붙인다. 현재 조문이 없으면 버린다 |
- 개정 표시 제거: 각 줄에서 `\s*<(?:개정|신설|전문개정|본조신설|제목개정)[^>]*>` 와 `\s*<\d{4}\.\d{1,2}\.\d{1,2}>` 를 지운다.
- 결과 조문: `doc_id = "law:민법:<조>-<가지 또는 0>"`, `law_name="민법"`, `article_no`, `article_branch_no`, `article_title`, `body`(항·호 포함 전체, `①` 표시 유지), `effective_on = None`(파일에 시행일 없음), `source_file = "law/민법.txt"`, `source_line` = 조 머리 줄 번호.
- 같은 `doc_id`가 두 번 나오면 `ImportIssue(DUPLICATE_ARTICLE)`, 본문이 비면 `EMPTY_CONTENT`.
- 확인(2026-11-23, 위 규칙을 실제 `민법.txt`에 적용): 조문 1,116개(제1조~제1118조), 삭제 조문 77개 제외, 편·장·절·관 제목 142줄·특수 제목 2줄 제외, 삭제 호 3줄 제외, 중복·빈 본문·소속 없는 줄 0, 대괄호 제목(제50조) 정상.
- 법령 기준일·출처(법제처 현행, 내려받은 날짜)는 `data/MANIFEST.md`에 적는다(사람).

### 공통
- 텍스트 정제(`corpus.domain.text_clean.clean_text`): `<br>`·`<br/>`·`<p>` → 줄바꿈, 그 밖의 태그 제거, `html.unescape`, 줄 끝 공백 제거, 연속 빈 줄 1개로.
- 멱등: `ON CONFLICT (doc_id)`, `corpus_version`은 정제 후 내용 해시의 정렬 해시.
- 재수집 방법(REQ-093): `data/MANIFEST.md`에 판례 수집 절차(`law_collector/README.md`)와 민법 내려받기 출처·날짜, 빈 본문 삭제 건수를 적는다(사람).

## 결과
- 좋아지는 점: 수집 결과를 옮기지 않고 바로 가져옴, 범위 밖 법령이 색인에 들어갈 경로 차단, 빈 본문 삭제 누락을 고정 단계에서 잡음
- 감수할 점: 판례 API 응답·민법 텍스트 형식에 의존, 하급심·오래된 판례 포함 → 대법원 법리와 다른 판단이 검색될 수 있음(실패 분석·보고서 한계)
- 후속 작업: TKT-BE-M2-01(정제·파서·변환 도메인), TKT-BE-M2-02(가져오기 서비스), TKT-DB-M2-01(수집기 형식 시험 데이터), 사람: 빈 본문 판례 일괄 삭제·MANIFEST

## 쉬운 설명
- A. 받은 파일을 그대로 읽기(선택): 무엇이 달라지나 — 수집기가 저장한 판례 파일과 내려받은 민법 텍스트를 가져오기 명령이 직접 읽어 태그·개정 표시를 지우고 조문 단위로 나눈다. / 좋은 점 — 따로 변환할 필요가 없다. / 감수할 점 — 파일 형식이 바뀌면 가져오기를 고쳐야 한다. / 나중에 바꾸기: 쉬움.
- B. 수집기에 변환 명령 추가: 무엇이 달라지나 — 수집기가 정해진 형식 파일을 만들어 준다. / 좋은 점 — 설계를 덜 고친다. / 감수할 점 — 팀 공용 수집기를 고쳐야 하고 시험이 없다. / 나중에 바꾸기: 쉬움.
- 판례는 데이터출처 "대법원"의 민사 판례 전부(하급심 포함, 약 4.25만 건)를 넣고, 판시사항·판결요지가 모두 빈 판례는 수집이 끝난 뒤 사람이 지운다.

## 개정
- 2026-11-23: 실제 수집 파일 확인 반영(§2-8 ② 세부 수정, 사용자 지시) — 민법 입력을 `민법.json`(API 응답)에서 `민법.txt`(일반 텍스트)로, 판례 선별에서 `법원명 == "대법원"` 조건 제거(데이터출처 대법원 전부, 사용자 결정), 빈 본문 판례는 사람이 수집 완료 후 일괄 삭제.
