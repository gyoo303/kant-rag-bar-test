# ADR-015: 원문 가져오기 — `law_collector` 출력을 그대로 읽기
- 상태: Accepted (user, 2026-11-23) — 옵션 A, 판례 범위는 대법원 민사 전부
- 대체: ADR-007 (Superseded by ADR-015)
- 관련 계층: [인프라] [모듈 협력 구조]
- 근거: ADR-007, CR-002, CR-003, CR-004, TR-07, Q-002·Q-008·Q-009 답, REQ-004, REQ-093, RISK-03

## 맥락
판례·민법 원문은 저장소의 `law_collector/collect.py`(파이프라인 밖, 사용자 팀 도구)가 별도로 수집한다(사용자 확인 2026-11-23). 그 출력은 ADR-007의 JSONL 계약과 다르다.
- 판례: `law_collector/data/prec/{판례정보일련번호}.json` — 판례 1건 = 파일 1개, 법령 API `PrecService` 응답 그대로(필드: `판례정보일련번호`, `사건명`, `사건번호`, `선고일자`, `법원명`, `사건종류명`, `판시사항`, `판결요지`, `참조조문`, `참조판례`, `판례내용`), 본문에 `<br/>` 등 HTML 태그 포함.
- 법령: `law_collector/data/law/{법령명}.json` — `lawService.do?target=law` 응답 그대로(조→항→호→목 중첩), 기본 16개 법령.
- 수집 범위: 사건종류코드 400101(민사) 중 데이터출처 "대법원" 전부(목록 기준 42,541건, 1947년 판례 포함).

## 결정 (A)
- **입력 위치**: 설정 `[paths] raw_dir = "law_collector/data"`. 판례 `raw_dir/prec/*.json`, 법령 `raw_dir/law/민법.json`. **`민법.json` 외 법령 파일은 읽지 않는다**(Q-002 범위, Q-008 근거 없음 문항 보호). 읽지 않은 파일 이름은 가져오기 보고에 "범위 밖 파일 무시"로 적는다.
- **판례 선별**: `사건종류명 == "민사"` 그리고 `법원명 == "대법원"`인 파일 **전부**(건수 상한 없음, 사용자 결정). 아니면 `ImportIssue(reason="OUT_OF_SCOPE")`. `판시사항`·`판결요지`가 정제 후 둘 다 비면 `EMPTY_CONTENT`.
- **판례 필드 매핑**: `판례정보일련번호` → `doc_id = "prec:<값>"`, `사건명` → `title`(없으면 `사건번호`), `사건번호`, `법원명`, `사건종류명`, `판시사항` → `holdings`, `판결요지` → `summary`, `참조조문` → `referenced_articles`. `판례내용`·`참조판례`는 저장하지 않는다(Q-009: 요지+참조조문).
- **날짜**: `선고일자`는 숫자만 남겨 8자리(`YYYYMMDD`)면 날짜로, 아니면 `BAD_DATE`. `YYYY.MM.DD`·`YYYYMMDD`·`YYYY-MM-DD` 모두 허용.
- **텍스트 정제**(`corpus.domain.text_clean.clean_text`, 순수 함수): `<br>`·`<br/>`·`<p>` → 줄바꿈, 그 밖의 태그 제거, HTML 엔티티 해제(`html.unescape`), 줄 끝 공백 제거, 연속 빈 줄 1개로.
- **민법 조문 펼치기**: `법령.기본정보.법령명_한글 == "민법"` 확인, `법령.조문.조문단위`(1건이면 dict, 여러 건이면 list → 항상 list로)에서 `조문여부 == "조문"`만 사용(`전문` = 편·장·절 제목은 제외). 조문 텍스트 = `조문내용` + 각 `항.항내용` + 각 `호.호내용` + 각 `목.목내용`을 줄바꿈으로 이음(항·호·목도 dict/list 정규화). `doc_id = "law:민법:<조문번호>-<조문가지번호 또는 0>"`, `effective_on = 조문시행일자 또는 기본정보.시행일자`. 필드 경로는 공식 가이드 기준이며 실제 파일 확인은 TKT-BE-M2-01에서 한다(미확인).
- **원본 위치 기록**: `source_file`은 `raw_dir` 기준 상대 경로, `source_line`은 판례 1(파일 1건), 조문은 `조문단위` 순번.
- **멱등**: `ON CONFLICT (doc_id)`, `corpus_version`은 정제 후 내용 해시의 정렬 해시(ADR-006·03-db-schema 그대로).
- **재수집 방법(REQ-093)**: `data/MANIFEST.md`에 `law_collector/README.md` 절차와 실행 날짜·팀원 분담·건수를 적는다(사람).

## 결과
- 좋아지는 점: 수집 결과를 옮기지 않고 바로 가져옴, 범위 밖 법령이 색인에 들어갈 경로 차단
- 감수할 점: 법령 API 응답 구조에 의존(구조가 바뀌면 가져오기 수정), 1947년 등 오래된 판례 포함 → 현행 민법과 다른 법리가 검색될 수 있음(실패 분석·보고서 한계에 적음)
- 후속 작업: TKT-BE-M2-01(정제·변환 도메인), TKT-BE-M2-02(가져오기 서비스), TKT-DB-M2-01(수집기 형식 시험 데이터)

## 쉬운 설명
- A. 수집기 결과를 그대로 읽기(선택): 무엇이 달라지나 — 수집기가 저장한 판례 파일들과 민법 파일을 가져오기 명령이 직접 읽어 태그를 지우고 형식을 맞춘다. / 좋은 점 — 따로 변환할 필요가 없다. / 감수할 점 — 법령 사이트 응답 구조가 바뀌면 가져오기를 고쳐야 한다. / 나중에 바꾸기: 쉬움.
- B. 수집기에 변환 명령 추가: 무엇이 달라지나 — 수집기가 정해진 형식 파일을 만들어 준다. / 좋은 점 — 설계를 덜 고친다. / 감수할 점 — 팀이 함께 쓰는 수집기를 고쳐야 하고 시험이 없다. / 나중에 바꾸기: 쉬움.
- 판례는 대법원 민사 전부(약 4.25만 건)를 넣는다. 아주 오래된 판례도 들어가므로 보고서 한계에 적는다.
