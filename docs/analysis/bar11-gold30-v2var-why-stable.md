# 변형본에서 성능이 거의 떨어지지 않은 이유 — 원본 v6 vs 변형본 v6 (2022 색인)

> 작성 2026-11-26 · 브랜치 `verify-2022`
> - 비교: 원본 30문항 v6 (`20261126-142855-bar11-gold30-v6`) vs 변형본 v2 v6 조건 (b) 2022 색인 (`20261126-153117-bar11-gold30-v2var-v6`)
> - 코퍼스: 2022. 1. 1. 시행 법령 + 2022. 1. 10. 까지 선고 판례 (`index-2022@20220101`)
> - 근거 자료: `bar11-gold30-v2var-v6-tables.md`(지표), `bar11-gold30-v2var-v6-report.md`(변형본 리포트), `raw-data-contribution.md`(원자료 기여 측정, `scripts/analysis/raw_contribution.py`)

레드팀 변형본을 넣었는데도 모든 지표가 원본과 1~3%p 안에서 움직였다. 이유는 하나로 모인다.

**변형본이 바꾼 것은 주로 보기 배치와 일부 지문의 표현이고, 검색 대상인 법리·판례는 거의 그대로였다.** 그 법리·판례가 **판결요지 항목 단위로 정리된 원자료** 안에 있었다. 원자료 구조만으로 정답 근거의 93~94%를 키워드 검색 상위 5개 안에서 찾을 수 있었다.

## 1. 지표별 해석

| 지표 | 원본 → 변형 (b) | 해석 |
|---|---|---|
| 문항 정답 | 29 → **30** | 원본 오답(11)을 맞혔고 새로 틀린 문항은 없다. 다만 문 24 는 ④·⑤ 동점에서 앞 번호가 정답이었던 운이다. 실력으로 보면 29~30 |
| 지문 정답 / 유보 / 오답 | 137/0/2 → 137/2/2 | 오답 2개는 원본과 같은 해석 오류(24 ㄷ·26 ㄴ)의 반복이다. 유보 2개는 변형이 새로 만든 시점 지문이다 — 24 ㄹ 은 시행령이 색인 밖이고, 56-② 는 2022 당시 조문을 확신하지 못했다 |
| 확신 오답 | 2 → 2 | 변형이 새로 만든 확신 오답은 없다 |
| Recall@5 · Hit@5 · MRR | 97.8·97.8·0.853 → 95.0·96.5·0.832 | 2~3%p 하락. 지문 85% 는 원본 그대로라 같은 판례가 검색되고, 새로 쓴 21개에서만 조금 떨어졌다 (Hit@5 85.7%) |
| Recall@1 | 75.2 → 72.3% | 같은 이유 |
| Context Recall | 97.8 → 97.9% | 같다. 지문 검색 상위 5에 없던 정답 근거도 다른 지문 검색·연결 근거로 판단 입력에 들어왔다 (예: 46-③ 전원합의체) |
| 인용 Recall · Precision | 89.2·82.4 → 90.1·80.0% | 정답 근거를 인용하는 비율은 같다. 인용한 문서 중 정답 근거 비율만 소폭 하락 |
| 지문 A | 88.5 → 87.9% | 정답 근거로 맞히는 비율이 유지됐다 |
| 모든 지문이 A 인 문항 | 16 → 15 | 실행 변동 범위 안 |
| 인용 없이 단정한 판단 | 0 → 0 | 근거 없이 지어낸 판단은 두 경우 모두 없다 |
| 근거 밖 정답 | 2 → 3 | 셋 다 다른 문서를 인용했다 (11 ㄷ, 59-⑤, 66-④). 모델 기억 의존은 거의 없다 |
| 시간 | 38.0 → 40.8초 | 유보·동점 문항(24·56)에서 2차 검색·동점 재판단이 돌아 늘었다 |

## 2. 숨은 기여 요소: 구조화된 법리·판례 원자료

원자료와 정답 근거만으로 측정했다 (LLM·GPU 없음).

| 측정 | 원본 30 | 변형 — 원본 지문 120 | 변형 — 새 지문 21 |
|---|---|---|---|
| ① 결정 문장이 판례 항목·조문 청크 **하나 안에** 그대로 있음 | **142/142 (100%)** | **123/123 (100%)** | 23/26 (2개는 색인 밖 시행령) |
| ② 지문 글자 중 결정 문장과 겹치는 비율 (평균) | **0.49** | **0.49** | 0.20 |
| ③ 키워드 검색(BM25)만, 지문 문장만 질의 → Hit@5 | **93.5%** | **94.2%** | 81.0% |
| (비교) v6 전체 파이프라인 Hit@5 | 97.8% | 98.3% | 85.7% |

### 2-1. 판결요지 항목 단위 청크 — "한 청크 = 한 법리"

| 원자료 구조 | 값 |
|---|---|
| 판례 청크 | 36,087 (평균 498자) — 판결요지를 항목 `[n]` 마다 한 청크 |
| 조문 청크 | 4,968 (평균 209자) — 조문 하나 (긴 조문은 항 단위) |
| 판시사항이 붙은 판례 청크 | 88.8% |
| 참조조문이 붙은 판례 청크 | 86.8% |

- 결정 문장 265개(원본 142 + 변형 원본 지문 123)가 **모두 한 청크 안에** 있었다. 청크 경계에서 잘린 경우는 0이다.
- 판결요지는 대법원이 "쟁점 → 결론"으로 압축해 둔 문장이다. 그래서 청크 하나가 정답 근거 하나와 거의 1:1 로 맞는다.
- 그 결과 Precision@1 이 원본 76.3%·변형 73.8% 로 높다. 상위 1개가 곧 정답 근거인 경우가 많다.

### 2-2. 시험 지문 ≈ 판결요지 문장

| | 원본 30 | 변형 원본 지문 | 변형 새 지문 |
|---|---|---|---|
| 겹침 ≥ 0.5 인 지문 | 64/139 (46%) | 58/120 (48%) | 1/21 (5%) |
| 겹침 ≥ 0.7 인 지문 | 31/139 (22%) | 26/120 (22%) | 1/21 (5%) |

(겹침 = 지문 글자 중 결정 문장과 3글자 이상 연속으로 같은 부분의 비율)

- 선택형 지문은 판결요지 문장을 가져다 쓰고 주체·결론 한두 군데만 바꾼다. 같은 법률 용어와 문장 구조를 쓰므로 **키워드 검색만으로 93% 이상**을 찾는다.
- 변형본은 원본 지문 120개를 그대로 두었다. 그래서 이 겹침(0.49)과 검색 성공률(94.2%)이 원본과 같다. **검색 쪽에서 보면 변형본은 원본과 사실상 같은 시험이었다.**
- 새로 쓴 지문 21개는 겹침이 0.20 이다. 이 지문들에서만 검색이 떨어졌다.

### 2-3. 키워드 검색 vs 시스템

| 검색 방식 | 원본 30 | 변형 원본 지문 | 변형 새 지문 |
|---|---|---|---|
| BM25 단독, 지문 문장만 | 93.5% | 94.2% | 81.0% |
| v2 (BM25 + 벡터 → 리랭커, 발문 앞 300자 + 지문) | 87.8% | — | 61.9% |
| v6 (리라이트 + 원문 질의, RRF, 연결 지도) | 97.8% | 98.3% | 85.7% |

- v6 의 검색 장치가 더한 몫은 원자료 위에 **+4~5%p** 다.
- v2 가 BM25 단독보다 낮다. 질의 앞에 붙인 발문 300자(사례의 당사자·경위)가 판결요지와 겹치지 않아 질의를 흐렸다. v4 이후 '진술 원문 질의'를 따로 더한 것이 이 손실을 메웠다.

### 2-4. 메타데이터 — 방어 장치의 바탕

| 원자료 필드 | 쓰인 곳 | 이번 결과에서의 효과 |
|---|---|---|
| 판례 선고일 | 2022 색인, 기준일 필터, 미래 판례 숨김 | 기준일 뒤 판례 0건 → 판례 시점 공략(축 B) 성립 안 함 (판례 청크 39,268 → 36,087) |
| 법령 시행일 원문 (2022. 1. 1. 스냅숏) | 2022 법령 색인 | 개정 조문 공략(축 A) 5문항을 막음. 같은 문항을 2026 색인에서 풀면 5문항 모두 실점 |
| 참조판례 '(변경)' 표시 | 판례 변경 표시, 변경한 판례 연결 | 옛 법리 미끼(축 C) 4/4. 함정 판례가 판단 입력에 들어와도 인용 0 |
| 참조판례·참조조문 | 판례 → 판례, 조문 → 판례 연결 | 지문 검색 상위 5에 없던 전원합의체(46-③ 2015다45451)가 판단 입력에 들어가 A |
| 판결 항목 번호·조각 | 같은 판결 다른 항목 동봉, 조각 합치기 | 결정 문장이 잘리지 않음 |
| 판시사항 | 청크 머리의 쟁점 요약 | 지문 쟁점과 직접 맞는 짧은 문장 → 검색 적중 |

## 3. 그 밖의 이유

| 이유 | 해당 문항 | 설명 |
|---|---|---|
| 보기 배치 공략은 구조상 통하지 않음 | 축 D 16문항 → 16/16 | 모델은 진술마다 참·거짓만 판단하고, 정답 번호는 규칙으로 계산한다. 보기 순서가 바뀌어도 답이 따라 옮겨 간다 |
| 시점 공략은 2022 색인에서 성립하지 않음 | 축 A·B 6문항 → 6/6 | 함정 조문·판례가 색인에 없다. 최신 색인(조건 a)에서는 5문항 실점 |
| 새 지문이 2022 색인 원문을 옮겨 씀 | 새 지문 21개 | 출제자가 근거 문장을 원문 그대로 대조해 썼다 → 겹침은 낮아도 근거를 찾기 쉬움 (Hit@5 85.7%) |
| 나머지 공략은 이미 대비함 | 그럴듯한 이유(AP7)·옛 법리(C)·발문 문구(F) | v5·v6 에서 미리 고친 것. **발문 문구(F)는 이 변형본을 본 뒤에 고쳤다** |

## 4. 주의할 점

1. **정답 근거가 검색되기 쉬운 쪽으로 치우쳐 있다.**
   - 원본 30문항의 정답 근거는 한 에이전트 색인의 검색 후보 중에서 골라 확정했다.
   - 그리고 근거가 모두 확정된 문항만 뽑았다.
   - 그래서 키워드 검색 93.5% 는 시험 전체보다 높게 나온 값일 수 있다. 70문항 초안에서는 원자료에 없는 판례가 11건 나왔다.
2. **1회 실행이다.** 문항 1개 차이(29 → 30, 16 → 15)는 실행 변동 안에 있다.
3. **메타데이터 효과는 비교 실험으로 확인한 것이 아니다.** 실행 결과와 맞물려 확인한 것이고, 해당 기능만 끈 실험(ablation)은 하지 않았다.
4. **발문 극성·형식(축 F) 방어는 사후 수정이다.** 처음 보는 표현에 대한 방어 증거는 아니다.

## 5. 결론

변형본에서 지표가 원본 수준을 유지한 이유는 세 가지다.
1. 검색 대상인 법리·판례가 그대로였다.
2. 그것들이 **판결요지 항목 단위로 정리된 원자료**에 있었다.
3. **선고일·시행일·변경 표시 같은 메타데이터**가 시점·미끼 공략을 막았다.

원자료 구조만으로 정답 근거의 9할 이상이 이미 찾을 수 있는 위치에 있었고, v6 는 그 위에 4~5%p 를 더했다.

거꾸로, 이 구조 **밖의** 근거가 시스템의 실제 한계다.

| 약점 | 이번에 드러난 곳 |
|---|---|
| 판결요지와 다르게 쓴 지문 | 새 지문 겹침 0.20 → 검색 85.7% |
| 색인에 없는 하위 법령(시행령) | 24 ㄹ 유보 → 동점 운 |
| 판결 이유에만 있는 법리 | 이번 변형본에는 없음 — 다음 레드팀 대상 |
| 최신 색인에서의 개정 조문 | 조건 (a) 5문항 실점 |

다음 레드팀은 방어 쪽이 공략안을 보지 않은 상태에서 위 약점을 노리는 방식으로 하는 것이 시스템 한계를 드러내는 데 효과적이다.
