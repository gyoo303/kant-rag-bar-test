# 최종 테스트 지침 — RAG 에이전트 성능 지표

> 작성 2026-11-26 · 브랜치 `verify-2022` · 대상: 제11회(2022) 민사법 선택형 70문항 (`data/exam/bar11_civil.json`), 프리셋 v6, 색인 `index-2022/`(2022. 1. 10. 까지 선고 판례)
>
> 측정 3파트: **검색**(의미 있는 문서가 검색되었나) · **사실**(문제에 적합한 문서가 맥락으로 쓰였나) · **답변**(최종 답을 맞혔나)
> 세부 측정: ① 5개 지문을 정확한 근거로 판단했는가 ② 추가 추론(생성형 모델의 판단 개입)이 발생했는가

## 요약

- 세 파트를 Recall·Precision으로 재려면 **지문마다 정답 근거(gold)** 가 있어야 한다. 지금 근거 표기는 `eval/test.json` 17문항, 그것도 문항 단위뿐이다 → **지문 단위 정답 근거 만들기가 핵심 준비 작업**이다.
- 실행은 RAG 본실행 3회 + closed-book 3회 + 검색만 실행(LLM 없음) 1회.
- 지문을 A~E 다섯 칸으로 분류해 "정확한 근거로 맞혔는가"를, RAG × closed-book 교차표로 "모델 기억이 얼마나 개입했는가"를 본다.

## 0. 원칙: 테스트 전에 고정할 것

| 항목 | 내용 |
|---|---|
| 구성 고정 | 커밋 해시, 프리셋(v6), 색인(index-2022), 시험지, 정답표를 실행 전에 기록한다. 결과를 보고 설정·프롬프트를 바꾸면 그 결과는 최종 성능이 아니라 탐색 결과가 된다 |
| 반복 실행 | LLM 판단은 실행마다 조금씩 다르다. 3회 실행해 평균과 범위를 보고한다 (`eval --repeat 3`) |
| 비교 기준 | 같은 모델의 closed-book 결과를 반드시 함께 낸다. "RAG가 기여한 몫"과 "모델이 원래 아는 몫"을 나누는 기준이다 |
| 정답표 | 지금은 "정답가안"이다. 확정 정답이 나오면 `regrade --answers` 로 다시 채점한다 |
| 2022 검증의 한계 | 근거는 2022년 이전 판례로 막지만 모델은 그 뒤 판례를 학습했을 수 있다. 4-②에서 따로 센다 |

## 1. 실행 목록

| 실행 | 명령 요지 | 용도 |
|---|---|---|
| R1 RAG 본실행 ×3 | `eval data/exam/bar11_civil.json --modes hybrid_rerank --preset v6 --repeat 3` | 세 파트 모두 |
| R2 closed-book ×3 | `eval data/exam/bar11_civil.json --modes none --preset v6 --repeat 3` | 모델 단독 기준선, 추론 개입 측정 |
| R3 검색만 (LLM 없음) | 진술별 질의로 벡터 / 하이브리드 / 하이브리드+리랭커 top-k 만 저장 | 검색 방식별 Recall·Precision 비교. 판단 호출이 없어 저렴 |

R3 는 아직 없는 명령(`retrieval-eval`)이 필요하다 (6장).

## 2. 정답 근거 만들기 (가장 중요)

지문(보기 ①~⑤ 또는 ㄱ~ㅁ) 하나마다 참/거짓을 결정하는 조문·판례 항목을 1~3개 적는다.

| 단계 | 방법 |
|---|---|
| ① 후보 자동 수집 | 실행 기록에서 지문별 검색 top-10, 판단이 인용한 청크, 연결 근거, 2차 검색 근거를 모아 후보표(CSV)를 만든다 |
| ② 사람이 표시 | 후보 중 결정적 근거에 표시한다. 후보에 없으면 해설서·판례 검색으로 찾아 청크 id 를 적고 "검색 누락"으로 표시한다 |
| ③ 등급 | **결정적**(이것만으로 판단 가능) / **보조**(관련 있지만 단독으로 부족). Recall 은 결정적 기준, Precision 은 결정적+보조 기준 |
| ④ 일치 규칙 | 조문은 조 단위로 맞으면 인정 (항 단위 조각 `-1`·`-2` 포함). 판례는 사건번호+항목이 맞으면 인정, 같은 판례 다른 항목은 "부분 일치"로 따로 센다. 분할 조각(`~k`)은 원 항목과 같다 |
| ⑤ 교차 확인 | 팀원 2명이 20문항을 각자 표시해 일치율을 보고한다 (정답 근거 자체의 신뢰도) |

분량: 70문항 × 지문 약 4.6개 ≈ **320개**. 후보표가 있으면 지문당 1분 안팎.

## 3. 파트별 지표

### 3-1. 검색 — 의미 있는 문서가 검색되었나

지문마다 정답 근거 집합 G, 검색된 상위 k개 R_k.

| 지표 | 정의 | 비고 |
|---|---|---|
| **Recall@k** | \|G ∩ R_k\| ÷ \|G\| | k = 1, 3, 5, 10 |
| **Precision@k** | \|G ∩ R_k\| ÷ k | 결정적+보조 기준 |
| Hit@k | G 중 하나라도 R_k 에 있는 지문 비율 | 가장 직관적 |
| MRR | 첫 정답 근거 순위의 역수 평균 | 순위 품질 |
| 단계별 | 벡터 → BM25 → RRF 결합 → 리랭커 순위 변화 | 기록의 `retrieval` 에 단계별 순위가 있음 |
| 문서 종류별 | 조문 근거 / 판례 근거로 나눈 Recall | 판례 검색이 약한지 |

### 3-2. 사실 — 적합한 문서가 맥락으로 쓰였나

| 지표 | 정의 |
|---|---|
| **Context Recall** | 판단 입력(근거 묶음 `context_chunk_ids`)에 정답 근거가 들어간 지문 비율 |
| **Context Precision** | 근거 묶음 중 정답 근거(결정적+보조)인 청크 비율 — 잡음 수준 |
| 출처별 기여 | 정답 근거가 들어온 경로: 1차 검색 / 연결(판례 변경·조문→판례·판례→판례·준용·조문 위치·조문 제목) / 2차 검색 |
| **인용 Recall** | 판단이 정답 근거를 인용한 지문 비율 (넣어 준 근거를 실제로 썼는가) |
| **인용 Precision** | 판단이 인용한 청크 중 정답 근거 비율 |
| 인용 원문 일치율 | 판단의 `quote` 가 인용 청크 원문에 실제로 있는 비율 (환각 인용 검출) |

### 3-3. 답변 — 최종 답을 맞혔나

| 지표 | 정의 |
|---|---|
| **문항 정확도** | 정답 수 ÷ 70. 형식별(단일 43·조합 21·○× 6)·과목별(민법 1~35·민사소송법 36~51·상법 52~70), 3회 평균과 범위 |
| 지문 정확도 | 지문 판단 정답률, 유보율, 확신 오답(확신도 ≥ 0.9) 수 |
| 보정 | 확신도 구간별 실제 정답률 (0.9 판단이 실제로 90% 맞는가) |
| 상태 | 동점(tie), 판단 불일치, 오류 문항 수 |
| 비용 | 문항당 시간, LLM 호출 수, 토큰 |

## 4. 세부 측정

### ① 5개 지문을 정확한 근거로 판단했는가

지문마다 다섯 칸 중 하나로 분류한다.

| 분류 | 조건 | 해석 |
|---|---|---|
| **A 근거 기반 정답** | 판단 정답 + 정답 근거 인용 + 인용 원문 일치 | 의도한 RAG 동작 |
| B 근거 불일치 정답 | 판단 정답, 그러나 정답 근거를 인용하지 않았거나 인용이 원문과 다름 | 운 또는 모델 기억 |
| C 추론 실패 | 정답 근거가 근거 묶음에 있었는데 판단이 틀림 | 읽기·해석 문제 (프롬프트·모델) |
| D 검색 실패 | 정답 근거가 근거 묶음에 없고 판단이 틀림 | 검색 문제 |
| E 유보 | 판단 unknown | 근거 부족을 인정 |

문항 단위:

- **완전 근거 정답률** = 모든 지문이 A 인 문항 비율. 가장 엄격한 지표 ("답도 근거도 전부 맞다")
- 정답 문항 중 B 가 섞인 비율 = 답은 맞혔지만 근거가 불완전
- 오답 문항의 원인 = C 와 D 중 어느 쪽인가

### ② 추가 추론이 발생했는가 (생성형 모델의 판단 개입)

| 신호 | 측정 | 뜻 |
|---|---|---|
| **근거 밖 정답** | 정답 근거가 근거 묶음에 없는데 판단이 맞은 지문 | 모델 기억으로 판단 (2022 검증에서는 미래 지식 누설 가능성) |
| 인용 없는 판단 | `cited_chunk_ids` 가 비었거나 `source=knowledge` | 명시적 근거 없음 |
| 인용 불일치 | `quote_check` 가 false | 근거를 꾸며 냈을 가능성 |
| **RAG × closed-book 교차** | 지문마다 (RAG 맞음/틀림) × (closed-book 맞음/틀림) 4칸 | RAG만 맞음 = 검색의 순수 기여 · closed-book만 맞음 = 검색이 방해 · 둘 다 맞음 = 모델이 원래 알던 것 |
| 재판단 개입 | 2차 검색(`research`)·동점 재판단(`tiebreak`)·예비 규칙(`answer_check.flipped`)으로 바뀐 지문과 전후 정답 여부 | 추가 추론 단계의 득실 |
| 진술 풀어쓰기 | `restated` 가 원 진술과 뜻이 달라진 사례 (표본 검토) | 해석 단계 오류 |

핵심 요약 수치:

| 수치 | 식 |
|---|---|
| 근거 의존도 | A ÷ (A + B) |
| 기억 의존도 | 근거 밖 정답 ÷ 정답 지문 |
| RAG 순수 기여 | (RAG만 맞음) − (closed-book만 맞음) |

## 5. 보고서 형식

1. 요약: 문항 정확도(3회 평균·범위), closed-book 대비, 완전 근거 정답률
2. 검색: 방식별 Recall@k·Precision@k·MRR, 단계별 순위 변화
3. 사실: Context Recall·Precision, 출처별 기여, 인용 Recall·Precision·원문 일치율
4. 답변: 형식별·과목별 정확도, 지문 정확도, 확신 오답, 보정 그래프
5. 지문 분류 A~E 분포, 오답 문항 원인(C/D)
6. 추론 개입: RAG × closed-book 교차표, 근거 밖 정답, 재판단 득실
7. 한계: 정답 근거 일치율, 정답가안, 모델 학습 시점
