# 2026 변호사시험 민사법 선택형 70문항 — RAG vs closed-book 결과 및 오답 분석

> 작성 2026-11-24 · 브랜치 `sanghyuk` · 원자료: `results/`, 상세 분석: `docs/analysis/all70-v1.md`, `docs/analysis/all70-v2.md`

## 1. 요약

| | RAG (v2) | closed-book (v2) | 차이 |
|---|---|---|---|
| 정답 | **58/70 (82.9%)** | 40/70 (57.1%) | **+18문항** |
| 확신을 갖고 틀린 진술 | **10** | 57 | **−82%** |
| 판단 유보(unknown) 진술 | 53 | 0 | |
| 문항당 시간(중앙값) | 18.8초 | 36.2초 | RAG 가 1.9배 빠름 |

- **RAG 가 closed-book 보다 18문항 더 맞혔다.** RAG 만 맞힌 문항 22개, closed-book 만 맞힌 문항 4개.
- 핵심은 신뢰성이다. 근거 없이 푼 루나는 **모든 진술을 단정했고 57개를 틀렸으며, 틀린 진술의 평균 확신도가 0.90** 이었다. 프로젝트 주제인 "AI 가 틀리도록 낸 문제"에서 범용 AI 가 확신을 갖고 틀리는 모습이 그대로 나타났다. RAG 는 확신을 갖고 틀린 진술을 10개로 줄였고, 근거가 없을 때는 판단을 유보했다.
- 진술 단위 정확도는 closed-book(258/315)이 RAG(252/315)보다 약간 높다. RAG 가 유보한 53개 진술을 오답으로 세기 때문이다. 유보가 조합형·○×형 문항에 몰리면서 일부 문항을 잃지만, 문항 정답률은 RAG 가 크게 앞선다.
- RAG 가 가장 크게 도움이 된 함정은 **예외·단서(13→28/32)**, **부정 극성(19→31/36)**, 과목은 **민사소송법(7→14/16)**.
- RAG 의 오답 12문항은 v1·v2 가 동일하고, 정답 번호 계산 오류는 0건이다. 판단 오류 6건 모두 결정적 근거가 색인에 있었다 → 검색·근거 구성·프롬프트 개선 여지가 크다.

> ⚠ 두 실행 모두 70문항 전체를 푼 **탐색 실행**이며 최종 평가용 test 17문항이 포함되어 있다. 이 결과로 test 에 맞춰 튜닝하지 않으며, 최종 수치는 고정된 `eval/test.json` 으로 별도 산출한다 (경위는 §8).

## 4. RAG vs closed-book 상세

### 4.1 문항 교차표

| | closed-book 정답 | closed-book 오답 |
|---|---|---|
| **RAG 정답** | 36 | **22** (RAG 가 살림) |
| **RAG 오답** | 4 (RAG 가 망침) | 8 (둘 다 틀림) |

- **RAG 가 살린 22문항**: 6, 11, 12, 15, 18, 20, 23, 24, 29, 30, 31, 38, 40, 41, 42, 46, 47, 49, 51, 54, 62, 63 — closed-book 은 이 문항들에서 진술 1~3개를 확신도 0.77~0.99 로 잘못 단정했다 (예: 문 63ㄱ 0.99, 문 47ㄴ 0.99, 문 18② 0.98).
- **RAG 가 망친 4문항**: 28, 35, 43, 53 — 28·35 는 RAG 가 근거를 못 찾아 유보(closed-book 은 자체 지식으로 맞힘), 43·53 은 RAG 가 받은 근거를 잘못 적용(§5.3 판단 오류).
- **둘 다 틀린 8문항**: 2, 8, 9, 10, 13, 17, 19, 36 — 근거 누락·미수집과 판단 오류가 겹친 문항.

### 4.2 진술 단위 교차 (315개)

| RAG \ closed-book | 정답 | 오답 |
|---|---|---|
| 정답 | 211 | **41** |
| 유보(unknown) | **41** | 12 |
| 오답 | 6 | 4 |

- RAG 가 근거로 바로잡은 진술 41개, 근거를 못 찾아 유보했지만 closed-book 은 맞힌 진술 41개.
- RAG 의 오답 10개 중 6개는 closed-book 이 맞혔다 → 근거가 오히려 판단을 흐린 경우(일반 원칙만 검색되고 예외를 놓침, §5.3).

### 4.3 2단계 판단 모의 계산 (기존 기록으로)

RAG 가 유보한 진술만 closed-book 판단으로 채우면:

| | RAG v2 | 2단계(모의) |
|---|---|---|
| 70문항 | 58 | 59 (+1) |
| test 제외 53문항 | 44 | 45 (+1) |

8·10·28·35 를 살리지만 11·15·63 을 잃는다. 유보 진술의 23%(12/53)는 closed-book 도 틀리기 때문에, 유보를 기억으로 채우면 **확신을 갖고 틀리는 진술이 다시 늘어난다.** 2단계 판단은 정답률 이득이 작고 신뢰성을 해칠 수 있어 우선순위를 낮춘다. 적용하더라도 "근거 없음" 표시를 반드시 남겨야 한다.

시험 함정은 주로 **원칙의 예외**를 묻는데, 검색은 진술과 어휘가 겹치는 **일반 원칙**을 상위에 올린다. 루나는 받은 원칙을 문자 그대로 적용해 확신을 갖고 틀린다. 이 중 43·53 은 closed-book 이 맞힌 문항이다 — 잘못된 근거가 모델의 올바른 지식을 덮었다.

### 5.4 실행 간 변동

같은 설정인데 문 28 의 유보 진술이 ㄱ(v1) → ㄷ(v2), 문 13ㄴ 이 unknown(v1) → true 0.85(v2) 로 달라졌다. 최종 test 는 2~3회 반복 실행의 평균과 범위로 보고한다.

## 7. 결론

- 근거 검색을 붙인 루나는 같은 모델의 기억만으로 푼 경우보다 **18문항(25.7%p) 더 맞혔고, 확신을 갖고 틀린 진술을 57개 → 10개로 줄였다.** 특히 예외·단서와 부정 극성 함정, 민사소송법에서 효과가 컸다.
- 대가는 판단 유보다. 근거를 못 찾으면 답을 내지 않거나(2문항) 조합형에서 점수가 흔들린다. 유보를 기억으로 채우는 것은 이득이 작고 신뢰성을 해친다.
- 남은 오답의 핵심은 "원칙은 찾고 예외는 놓치는" 검색과, 받은 근거를 그대로 적용하는 판단이다. 결정적 근거가 이미 색인에 있으므로 검색·근거 구성·프롬프트 개선으로 줄일 수 있다.

## 8. 평가 규칙 준수 기록

- 70문항은 dev 8 · test 17 · extra 45 로 사전에 분리했다(seed 2026, 과목 비례). test 는 최종 평가 전용이다.
- 이 리포트의 세 실행은 시험 70문항 전체를 푼 탐색 실행이라 test 17문항이 포함되었다. 실행 시 경고를 출력했고, 결과는 탐색 기록으로만 쓴다.
- test 의 근거표·유형 분류는 **결과를 보기 전에** 작성했다. 결과를 본 뒤 프롬프트·검색 설정은 바꾸지 않았다. v1→v2 사이의 변경(909d0c0)은 응답 파싱·출력 한도 **버그 수정**이다.
- 개선안은 dev·extra 문항에서도 같은 패턴이 보인 것만 채택했고, test 문항(2, 10, 17)은 근거로 쓰지 않았다.
- 앞으로 튜닝은 dev + extra(53문항)로만 하고, test 는 `frozen: true` 고정 후 마지막에 반복 2~3회 실행한다.
