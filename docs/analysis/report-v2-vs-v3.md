# v2 vs 개선안 v3 — 코드·성능 비교 리포트

> 작성 2026-11-24 · 브랜치 `sanghyuk` · 근거: `docs/analysis/report-all70.md`(v2 분석), `docs/analysis/improvement-plan.md`(개선안) · 원자료 `results/`

## 1. 요약

| | v2 | a1 | a2 | a34 | **b** | c (=v3 전체) |
|---|---|---|---|---|---|---|
| 정답 (튜닝 53) | 44 | 43 | 49 | 50 | **51** | 48 |
| dev (8) | 5 | 5 | 6 | **8** | **8** | **8** |
| 확신 오답 진술 | 9 | 9 | **4** | 5 | 8 | 11 |
| 유보 진술 | 39 | 37 | 38 | 27 | 14 | 0 |

- **최고 구성은 b(A1~A4 + 판단 프롬프트 v2): 44 → 51/53 (+7, 83% → 96%).** dev 8문항은 a34 부터 전부 맞혔다.
- **가장 큰 기여는 A2(쿼리 리라이트, +6)** 이고, A3·A4(같은 판결 항목·준용 조문)는 설계 대상이던 문 9·53 을 정확히 살렸다.
- **c(closed-book 결합)는 48 로 b 보다 낮지만, 원인은 결합이 아니라 실행 간 변동이다.** c 실행의 결합 전 RAG 결과가 이미 48 이었고, 결합 자체는 1문항을 살리고(35) 1문항을 잃어(36) 순증감 0이었다.
- 비용: b 는 v2 대비 LLM 호출 2배(리라이트), 입력 토큰 1.6배, 출력 토큰 2.1배, 문항당 시간 19.5초 → 31.1초.
- 단일 실행 결과이고 실행 간 ±3문항 변동이 관찰되었으므로, **b·c 를 2~3회 반복해 확정한 뒤** test 를 고정·실행한다.

> 모든 비교는 튜닝 세트 53문항(dev 8 + extra 45, `data/exam/2026_civil_tune.json`)에서 했다. test 17문항은 쓰지 않았다.

### 3.1 파이프라인

```

문항 → 진술 분리                          문항 → 진술 분리
① 질의: 발문 앞 300자 + 진술              ① 리라이트: 진술마다 쟁점·예외 질의 2개          [A2]
② 진술별 검색                              ② 질의별 검색 → RRF 결합                         [A2]
```

## 5. 쟁점

### 5.1 c 가 b 보다 낮은 이유 — 실행 간 변동

| | 정답 |
|---|---|
| b | 51 |
| c 결합 전 (RAG 단계, `rag_predicted`) | 48 |
| c 결합 후 | 48 |

c 실행의 RAG 단계는 b 와 같은 설정인데 문 16·26·43 이 달라졌다(b 정답 → c 오답). 결합은 9문항에서 유보 진술 13개를 채웠고:

| 문 | 채운 진술 | 결합 전 → 후 | 결과 |
|---|---|---|---|
| 35 | ㄱ true, ㄹ true | ① → ④ | **살림** (판례 미수집 문항) |
| 36 | ㄱ·ㄷ·ㄹ true | ② → ⑤ | **잃음** — ㄹ(소가 3억 원 항소 관할)을 지식으로 오판. 사물관할 규칙 미수집, b 의 근거 판단도 ㄹ 을 틀렸음 |
| 15, 31, 33, 51, 56, 59, 61 | 1~2개 | 변화 없음 | |

지식 판단 진술 13개 중 10개 정답·3개 오답(77%). 결합의 순효과는 0이며, 정답 수보다 **유보를 없애는 대신 확신 오답이 늘어나는**(b 8 → c 11) 효과가 크다.

### 5.2 유보와 확신 오답의 맞교환

유보 진술: v2 39 → a34 27 → b 14 → c 0. 확신 오답: a2 4 → b 8 → c 11.
B 프롬프트의 "핵심 법리가 있으면 판단" 규칙이 유보를 크게 줄였지만, 일부는 틀린 단정으로 바뀌었다.

- 예: 문 61ㄴ — v2 는 유보했으나 b 는 **발기설립** 조문(상법 제300조)을 **모집설립** 사안에 적용해 true(0.82)로 오판. 프롬프트의 "사실관계 동일성 확인"이 조문(설립 방식)에는 충분히 작동하지 않았다.

### 5.3 실행 간 변동

같은 설정에서도 문항 2~3개가 실행마다 뒤집혔다(v2→a1 의 5·61, b vs c RAG 단계의 16·26·43). 단일 실행 차이 ±3문항은 노이즈 범위일 수 있다. **b 와 c 를 각 2~3회 반복**해 평균·범위로 확정해야 한다.

## 6. 결론과 권장

1. **기본 구성은 b** — 정답 51/53(96.2%), dev 8/8, 확신 오답 8. v2 오답 9문항 중 8문항 해결.
2. **A2(리라이트)가 핵심 개선** (+6). 발제 필수 실험인 C vs C+리라이트의 효과가 뚜렷하다.
3. **A3·A4 는 설계대로 작동**(문 9·53). 비용(입력 +16%) 대비 효과가 있다.
4. **C(결합)는 기본에서 제외, 옵션으로 유지** — 순효과 0, 확신 오답 증가. 쓰려면 "지식 판단(근거 없음)" 표시를 필수로 한다.
5. 남은 과제
   - 사물관할 규칙 등 대법원규칙 수집 (문 36)
   - 조문 적용 시 사실관계(설립 방식 등) 확인 강화 (문 61)
   - b·c 반복 실행 2~3회로 변동 범위 확인 → 구성 확정 → `eval/test.json` 고정 → test 최종 실행(v2 · b · closed-book, 반복)
