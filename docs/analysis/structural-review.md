## 1. 평가 설계 (결론의 신뢰도)

### 1.1 깨끗한 평가 데이터가 거의 남지 않았다 🔴

| 데이터 | 상태 |
|---|---|
| 2026 dev·extra (튜닝 53) | v3·v4 설계와 프리셋 선택에 반복해서 사용 → **튜닝 세트에 과적합되었을 수 있음** |
| 2026 test 17 | 아직 고정 전. 70문항 탐색 실행(v1·v2·closed-book)과 변형본 실행에서 **결과를 이미 봤다** (설정 근거로 쓰지는 않음) |
| bar13 | v3 의 "처음 보는 시험"이었지만, 오답 분석이 v4 설계에 들어갔다 → **v4 평가에는 더 이상 깨끗하지 않음** |
| 2026 변형본 | test 문항 포함, 정답 유지 여부 미검증(확인 필요 102개) |

→ v4 가 "처음 보는 시험에서도 낫다"고 말하려면 **새 시험 1회분**(예: 다른 회차 민사법)을 확보해 구성을 확정할 때까지 열어 보지 않아야 한다. 지금 test 17 은 최종 수치용으로만 쓰고, 고정은 `freeze-test` 로 커밋과 함께 남긴다.

### 1.2 표본이 작다 🔴

- 튜닝 53문항에서 1문항 = 1.9%p. 같은 설정 실행 간 변동이 ±2~3문항(4~6%p)이 관찰됐다.
- v2 44 → b 51 은 변동보다 크지만, **b 51 vs c 48, v3 vs v4 같은 비교는 단일 실행으로는 판단할 수 없다.**
- 대응: `eval --repeat 3` 으로 평균·범위를 내고, 같은 문항 쌍 비교(맞음/틀림 교차표의 불일치 칸)로 **McNemar 검정**을 붙인다. 진술 단위(약 240개)로 보면 검정력이 조금 낫다.

### 1.3 closed-book 기준선이 시험마다 다르게 유리하다 🔴

| 시험 | closed-book | RAG | 차이 |
|---|---|---|---|
| 2026 (제15회) | 40/70 (57%) | 58 (v2) | +18 |
| bar13 (과거 회차) | **53/70 (76%)** | 65 (v3) | +12 |

같은 모델인데 과거 시험에서 closed-book 이 19%p 높다. 과거 시험과 해설이 모델 학습 데이터에 들어 있을 가능성(**기억 오염**)이 크다. 그러면 과거 시험에서는 "RAG 의 효과"가 작게 보이고, closed-book 이 맞힌 문 23·65 같은 사례도 실력이 아니라 기억일 수 있다.
→ 보고서에서 RAG 효과의 주 근거는 **모델 학습 이후 시행된 2026 시험**으로 삼고, 과거 시험은 보조 근거로 표시한다.

### 1.4 진술 단위 정답은 정답 번호에서 역산한 값이다 🟡

- `derive_statement_labels` 는 "정답 보기와 맞는 진술 조합"으로 각 진술의 참·거짓을 정한다. 시험 문항에서는 맞지만, **변형본처럼 진술을 바꾸고 정답 번호만 유지한 데이터에서는 틀릴 수 있다.** (`variant_check.csv` 로 사람 확인 필요)

## 2. 데이터 (근거의 범위·시점)

### 2.1 법령이 한 시점(2026-01-01)뿐이다 🟠

- 판례는 `retrieval.case_date_to` 로 시점을 맞출 수 있게 했지만, **법령은 시점 필터가 없다.** 과거 시험(bar13)을 2026 법령으로 풀면, 그 사이 개정된 조문(예: 2024 상법·민법 개정)에서 정답표와 어긋난다.
- 대응: `fetch-laws` 가 시행일을 인자로 받게 해 **시험 연도별 법령 스냅숏**(`statutes/<시행일>/`)을 두고, 색인도 시점별로 만든다. 최소한 과거 시험 리포트에는 "법령은 2026 기준"을 명시한다.

### 2.2 시행령·규칙·특별법이 없다 🟠

색인에 있는 건 법률 13개 + 사물관할 규칙(수집 예정)뿐이다.

| 빠진 것 | 영향 예 |
|---|---|
| **상법 시행령** | 상법 제542조의11 "대통령령으로 정하는 상장회사"(자산 2조 원 기준 등). 상법에만 "대통령령으로 정하는"이 53곳 |
| **소송촉진 등에 관한 특례법** | 지연손해금 이율(연 12%) — bar13 문 27. 판례 속 언급(355개 청크)으로만 간접 확보 |
| 이자제한법, 보증인 보호를 위한 특별법, 신탁법, 공탁법 | 민법 사례형 단골 |
| 민사소송규칙, 민사집행법 시행령 | 절차 세부 (기간·방식) |

→ 문서 목록(`data/documents.csv`)에 추가하고 `fetch-laws` → `build-index`. 시행령은 조문 수가 많으니 민사 관련만.

### 2.3 판례는 판결요지만 있다 🟡

- 판결 **이유**가 없어, 요지에 드러나지 않은 사실관계·전제(예: "누적적 근저당에서 물상보증인이 먼저 경매된 경우")로 판례를 구별하기 어렵다. 판단 프롬프트 v4 가 "사실관계 동일성 확인"을 요구하지만 근거 쪽에 사실관계가 없다.
- 대응: 판례 API 의 판례내용(이유) 앞부분 일부를 별도 청크(`kind="facts"`)로 넣어 비교 실험.

## 3. 판단·점수 계산 (구조)

### 3.1 확신도가 보정되지 않았다 🟠

- 확신도는 모델의 자기 평가다. 변형본 실행에서 판단의 **40%가 1.0**이었다. 그런데 보기 점수는 `0.5 + 0.5×확신도` 의 **곱**이라 1.0 이 많으면 0점·동점이 생긴다(bar13 문 23, 변형본 문 55). v4 의 예비 규칙·동점 재판단은 증상 처리다.
- 대응: 튜닝 세트 진술(약 240개)의 "확신도 구간별 실제 정답률"로 **보정 곡선**(Platt/isotonic)을 만들어 점수 계산 전에 바꾼다. 곱 대신 **로그 우도 합**으로 바꾸면 해석도 쉬워진다.

### 3.2 진술을 한 번의 호출로 같이 판단한다 🟠

- 장점은 비용이지만, 한 진술의 판단이 다른 진술 판단에 영향을 줄 수 있다(조합형에서 "적당히 맞추기"). 실행 간 변동의 한 원인이기도 하다.
- 샘플링 파라미터를 지정하지 않아(`generation/llm.py`) 같은 입력에도 결과가 달라진다.
- 대응: (a) 확신도가 낮거나 갈리는 진술만 **따로 한 번 더** 판단해 다수결(자기 일관성), (b) 판단 순서를 섞어 2회 판단해 일치할 때만 확신. 비용이 늘어나니 동점·불일치 문항에만 적용.

### 3.3 인용 검증이 형식만 본다 🟠

- `invalid_citation` 은 "인용한 ID 가 검색 결과에 있었는가"만 확인한다. **그 근거가 판단을 실제로 뒷받침하는지**는 아무도 보지 않았다(사람 채점 `grading.csv` 미실시).
- 대응: 판단 출력에 근거의 **인용 문장**(evidence quote)을 넣게 하고, 그 문장이 해당 청크에 그대로 있는지 코드로 대조. 그다음 표본 30~50개를 사람이 채점해 "근거 적합률"을 보고서에 넣는다.

### 3.4 "모름"과 지식 결합의 경계가 흐리다 🟡

- 판단 프롬프트 v2 이후 "모름"이 거의 사라졌다(bar13 0개). 근거가 부족한데도 판단하는 경우가 늘었을 수 있다 — 확신 오답이 a2 4 → b 8 로 늘어난 것과 같은 흐름이다.
- 대응: 확신 오답 수를 구성 비교의 **1차 지표**로 같이 보고(정답 수만 보지 말 것), 근거 적합 채점과 묶어 본다.

## 6. 우선순위 제안

1. **평가 신뢰도 먼저**: 반복 실행(`--repeat 3`) + 대응 비교 검정으로 v3 vs v4 결론 내기 → 새 시험 1회분 확보·봉인 → test 고정.
2. **데이터 범위**: 상법 시행령, 소송촉진법, 이자제한법, 보증인보호법 추가 (코드 변경 거의 없음, 수집만).
3. **확신도 보정 + 인용 문장 대조**: 점수 계산의 근본 문제와 근거 신뢰성 둘 다 해결.
4. 판결 이유 일부 추가, 진술별 재판단은 비용을 보고 선택.

1번 중 반복 집계·재채점·고정 명령은 이미 있다. 2·3번은 코드 작업이 필요하다(2번은 문서 목록 추가 수준).
