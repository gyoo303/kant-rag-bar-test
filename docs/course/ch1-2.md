## 1-1. RAG 개념과 등장 배경

- **핵심 개념**
  - LLM 한계: **지식 컷오프(Knowledge Cutoff)**, **환각(Hallucination)**
  - RAG = 답변 생성 전 외부 DB에서 근거를 검색(Retrieve)해 프롬프트에 주입 후 생성(Generate) — "암기식 시험 → 오픈북 시험"
  - RAG vs 파인튜닝: RAG는 "새로운 지식 서가" 주입(실시간 갱신·출처 제시·저비용), 파인튜닝은 "말투·행동 양식" 체화(문체/페르소나, 엄격한 JSON 포맷)
- **사용 기술**: `langchain`, `langchain-core`, `langchain-openai`, `python-dotenv`; `init_chat_model`(벤더 비종속 LLM 생성 함수), `ChatPromptTemplate`, `StrOutputParser`; 모델 `gpt-5-mini`, `temperature=0`
- **환경**: `uv init chapter01-1 --python 3.13`, 노트북 `practice_rag_intro.ipynb`
- **대표 코드**: 단순 LLM 체인(`prompt | model | parser`) vs RAG 프롬프트(system에 `[참고 문서]:\n{context}` 변수) 비교. 검색 결과는 문자열로 가정해 `{context}`에 직접 주입
- **주의/권장**
  - RAG 시스템 프롬프트: "문서에 나와 있지 않은 내용은 절대로 지어내지 말고 모른다고 답변하세요."
  - 규정·가격표처럼 자주 바뀌는 지식, 근거 링크가 필요한 경우 → RAG 선택

## 1-2. RAG 파이프라인 5단계 구조

- **핵심 개념**
  - 5단계: ① 수집(Loading) → ② 분할(Chunking) → ③ 임베딩·저장(Embedding & Storing) → ④ 검색(Retrieval) → ⑤ 생성(Generation)
  - **인덱싱 단계**(①~③, 질문 전 배치/사전 작업) vs **질의 단계**(④~⑤, 실시간)
  - 단계별 병목: 수집(스캔본·표 깨짐) / 분할(청크 과소·과대, 문맥 단절) / 임베딩(도메인 용어 의미 반영 실패) / 검색(저품질 청크, k 부족) / 생성(지시 불이행, 환각)
- **사용 기술**: + `langchain-text-splitters`, `numpy`
  - `from langchain_text_splitters import RecursiveCharacterTextSplitter`
  - `from langchain_openai import OpenAIEmbeddings` — `model="text-embedding-3-small"`
  - `from langchain_core.vectorstores import InMemoryVectorStore`
  - 분할 설정: `chunk_size=90`, `chunk_overlap=20`; 검색 `k=1`
- **환경**: `uv init chapter01-2 --python 3.13`; `uv add ipykernel langchain langchain-core langchain-openai langchain-text-splitters python-dotenv numpy`; 노트북 `practice_rag_pipeline.ipynb`
- **대표 코드**
  ```py
  splitter = RecursiveCharacterTextSplitter(chunk_size=90, chunk_overlap=20)
  split_docs = splitter.create_documents([raw_text])
  embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
  vector_store = InMemoryVectorStore.from_documents(documents=split_docs, embedding=embeddings)
  retriever = vector_store.as_retriever(search_kwargs={"k": 1})
  context_chunk = retriever.invoke(user_query)[0].page_content
  ```
- **주의/권장**: chunk_overlap은 문맥 단절 방지 목적. 오답 발생 시 5단계 중 어디서 결함이 생겼는지 단계별로 추적·진단할 것

## 1-3. 임베딩과 벡터 표현

- **핵심 개념**
  - 임베딩 = 문장의 의미를 고차원 숫자 배열(벡터)로 변환; 의미가 비슷하면 의미 공간(Semantic Space)에서 가까움
  - 차원(Dimension) = 의미 측정 기준 축의 개수 (text-embedding-3-small = 1,536차원)
  - 코사인 유사도로 질문과 가장 가까운 문서를 문맥으로 선정 → LLM 답변
- **사용 기술**: `OpenAIEmbeddings(model="text-embedding-3-small")`, `embed_query(str)`(단일 문자열 → float 리스트), `embed_documents(list)`; `numpy`로 코사인 유사도 직접 구현; `gpt-5-mini`, `temperature=0`
  - 모델 비교표: `text-embedding-3-small`(OpenAI, 1,536차원, 8,191토큰, 범용·비용효율) / `text-embedding-3-large`(3,072차원, 8,191토큰, 고정밀 법률·의료) / `bge-m3`(BAAI 오픈소스, 1,024차원, 8,192토큰, 로컬 보안·다국어)
- **환경**: `uv init chapter01-3 --python 3.13`; `uv add ipykernel langchain langchain-core langchain-openai python-dotenv numpy`; 노트북 `src/chapter01_3/practice_embedding.ipynb`
- **대표 코드**
  ```py
  query_vector = embeddings_model.embed_query(user_question)
  doc_vectors = embeddings_model.embed_documents(corpus_documents)
  def cosine_similarity(v1, v2):
      return np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2))
  scores = [cosine_similarity(query_vector, d) for d in doc_vectors]
  selected_context = corpus_documents[int(np.argmax(scores))]
  ```
- **주의/권장**: 임베딩 모델 선택 기준 = 도메인 적합성, 인프라 비용(차원↑ → 메모리·인덱싱 비용 선형 증가), 한국어/다국어 지원 사전 검증. 임베딩 단계 의미 왜곡은 파이프라인 전체의 치명적 병목

## 1-4. 벡터 유사도 검색 원리

- **핵심 개념**
  - 유사도 척도 3종: **코사인 유사도**(-1~1, 문서 길이 왜곡 없음 → 자연어 검색 표준) / **유클리디안 거리**(0~∞, 0에 가까울수록 유사) / **내적**(정규화된 벡터에선 코사인과 동일, 초고속)
  - 전수 조사(Brute-force K-NN)는 데이터 증가에 따라 연산량 선형 증가 → 대규모에선 실시간 서빙 불가
  - **ANN(근사 최근접 이웃)**: 공간 사전 군집화(Clustering) 후 후보군만 탐색, 약간의 Recall을 양보하고 속도 개선 (트레이드오프), 벡터 인덱스(Vector Index)
- **사용 기술**: + `scikit-learn`(설치만, 코드는 numpy로 구현); `OpenAIEmbeddings("text-embedding-3-small")`, `gpt-5-mini`, `temperature=0`
- **환경**: `uv init chapter01-4 --python 3.13`; `uv add ipykernel langchain langchain-core langchain-openai python-dotenv numpy scikit-learn`; 노트북 `practice_vector_search.ipynb`
- **대표 코드**

- **주의/권장**: OpenAI 임베딩은 정규화되어 있어 코사인≈내적 값이 동일하게 나옴(실습 출력). temperature=0 → 임의적 상상 억제, 문맥 기반 일관 답변

## 1-5. 청킹 전략

- **핵심 개념**
  - 청킹 필요성: 입력 토큰 한계, 의미 선명도 유지(긴 문서 통째 임베딩 시 주제 혼합), 검색 효율
  - 분할 전략 3종: **고정 크기**(`CharacterTextSplitter`, 빠르지만 단어·문맥 단절) / **재귀적 문자**(`RecursiveCharacterTextSplitter`, 문단→문장→공백 순 구분자 적용, "범용 표준") / **의미론적 분할**(Semantic Chunking: 인접 문장 코사인 유사도가 임계값 이하로 급락하는 Breakpoint에서 분리, 응집도↑ 대신 인덱싱 시 임베딩 호출 多 → 레이턴시·비용)
  - 트레이드오프: 청크 작음 → 검색 정밀↑·문맥 누락 / 큼 → 문맥 풍부·노이즈↑; 오버랩 큼 → 연속성↑·중복/저장 공간↑
- **사용 기술**: `from langchain_text_splitters import CharacterTextSplitter, RecursiveCharacterTextSplitter`; `.split_text(str)`
  - 실습 설정값: 고정 `separator="", chunk_size=15, chunk_overlap=0` / 재귀 `chunk_size=35, overlap=0` / 오버랩 실습 `chunk_size=25, chunk_overlap=10` / QA 체인 `chunk_size=50, chunk_overlap=10`
  - 의미론적 분할은 개념 설명만 (코드 없음)
- **환경**: `uv init chapter01-5 --python 3.13`; `uv add ipykernel langchain langchain-core langchain-openai langchain-text-splitters python-dotenv`; 노트북 `practice_chunking.ipynb`
- **대표 코드**
  ```py
  text_splitter = RecursiveCharacterTextSplitter(chunk_size=50, chunk_overlap=10)
  chunks = text_splitter.split_text(raw_document)
  selected_chunk = chunks[1]   # 실습에선 관련 청크를 수동 선택
  rag_chain.invoke({"context": selected_chunk, "question": user_query})
  ```
- **주의/권장**: 사실 기반 답변엔 `temperature=0`. 재귀적 분할이 범용 텍스트 처리의 표준

## 1-6. 메타데이터 설계

- **핵심 개념**
  - 메타데이터 = 청크의 "규격화된 신분증": 시간적 유효성 구분, 출처 추적성(Traceability), 검색 비용 절감
  - 스키마 3대 분류: **식별**(`source`, `doc_id`, `author`) / **시간**(`created_at`, `updated_at`, `year`) / **구조**(`section`, `page`, `chunk_id`)
  - 필터링: **사전 필터링(Pre-filtering)** = 조건 충족 청크만 먼저 거른 뒤 유사도 계산 / **사후 필터링(Post-filtering)** = 유사도 검색 후 조건 불일치 제거
- **사용 기술**: `from langchain_core.documents import Document` (`page_content`, `metadata` dict); `RecursiveCharacterTextSplitter(chunk_size=40, chunk_overlap=0).split_documents([...])` → 원본 메타데이터가 각 청크에 계승; 필터링은 파이썬 리스트 컴프리헨션으로 구현(벡터 DB 미사용)
- **환경**: `uv init chapter01-6 --python 3.13`; `uv add ipykernel langchain langchain-core langchain-openai langchain-text-splitters python-dotenv`; 노트북 `src/chapter01_6/practice_metadata.ipynb`
- **대표 코드**
  ```py

  chunked_docs = text_splitter.split_documents([doc])
  for idx, d in enumerate(chunked_docs):

  ```
- **주의/권장**: 출처·날짜가 없으면 구버전/최신 규정이 섞여 오답. 메타데이터 예시 키: `source`, `page`, `category`, `year`. 답변에 출처 표기를 프롬프트로 강제

## 2-1. 문서 로딩

## 2-2. 텍스트 청킹 구현

- **핵심 개념**
  - `split_text()`: 문자열 → 문자열 리스트 / `split_documents()`: Document 리스트 → 분할, **원본 metadata를 모든 청크에 자동 복제(메타데이터 전파, Metadata Propagation)**
  - `chunk_size`(최대 문자 수), `chunk_overlap`(인접 청크 중복 문자 수 → 주어·목적어 단절 방지)
- **사용 기술**: `RecursiveCharacterTextSplitter(chunk_size=80, chunk_overlap=20, length_function=len, is_separator_regex=False)`
- **환경**: `uv add ipykernel langchain langchain-core langchain-community langchain-openai langchain-text-splitters python-dotenv pymupdf`; 노트북 `src/chapter02_2/practice_text_chunking.ipynb`
- **대표 코드**
  ```py
  text_splitter = RecursiveCharacterTextSplitter(chunk_size=80, chunk_overlap=20,
                                                 length_function=len, is_separator_regex=False)
  split_documents = text_splitter.split_documents([source_document])  # metadata 전파
  # 프롬프트: "[참고 청크]:\n{context}\n\n[문서 속성]: 파일={source}, 페이지={page}"
  #          + "[출처: 파일명 (페이지쪽)] 형식으로 근거를 명시"
  ```
- **주의/권장**: 메타데이터 보존을 위해 Document 단위 분할(`split_documents`) 사용. 실습에선 관련 청크를 수동 선택(`split_documents[0]`)

## 2-3. 청킹 품질 실험·비교

- **핵심 개념**
  - 청크 크기 트레이드오프 표: **소형(50~100자)** 단답형 사실 검색 유리·인과관계 유실 → FAQ·사전 / **중형(200~500자)** 문맥·정밀도 균형 → 일반 학사 규정·업무 매뉴얼 / **대형(800자 이상)** 문맥·서사 보존, 노이즈·토큰↑ → 계약서·법률 조항·논문
  - 실험: 소형 청크는 "특수 도서" 조건이 누락된 조각이 선택되어 답변 불가, 대형 청크는 정답 → 문맥 단절(Context Loss) 실증
  - "의미론적 분할" = `separators` 우선순위로 문단/문장 경계 우선 분할 (이 강의의 정의)
- **사용 기술**
  - 소형 `RecursiveCharacterTextSplitter(chunk_size=60, chunk_overlap=15, length_function=len)` / 대형 `chunk_size=380, chunk_overlap=30`
  - 구분자 분할 `RecursiveCharacterTextSplitter(chunk_size=120, chunk_overlap=20, separators=["\n\n", "\n", ".", " "], is_separator_regex=False)` → 조항(제N조) 단위로 깔끔하게 3청크
- **환경**: 2-2와 동일 패키지; 노트북 `src/chapter02_3/practice_chunking_comparison.ipynb`
- **대표 코드**
  ```py
  semantic_splitter = RecursiveCharacterTextSplitter(
      chunk_size=120, chunk_overlap=20,
      separators=["\n\n", "\n", ".", " "], is_separator_regex=False)
  semantic_chunks = semantic_splitter.split_text(library_rules)
  ```
- **주의/권장**: 문서 성격에 맞춰 chunk_size/overlap을 비교 실험해 답변 품질로 최적점 선택. 프롬프트에 "내용에 언급되지 않은 사실은 절대 지어내지 마세요."

## 2-4. 임베딩 생성

- **핵심 개념**
  - `embed_query()`(런타임 질의 1건) vs `embed_documents()`(청크 리스트 배치 — 한 번의 네트워크 요청으로 다수 처리)

- **사용 기술**

  - `from langchain_classic.embeddings import CacheBackedEmbeddings`, `from langchain_classic.storage import LocalFileStore`

  ```py
  store = LocalFileStore("./cache/")

  ```
- **주의/권장**: 캐시는 `embed_documents` 결과(document_embedding_cache)에 적용. namespace로 캐시 영역 분리

## 2-7. 인덱싱 파이프라인 통합·증분 갱신

- **핵심 개념**
  - 통합 인덱싱 파이프라인 = 로딩→분할→임베딩→DB 적재를 단일 흐름으로 결합 (교안은 "입력 경로만 전달하면 자동 완료"라고 설명하나, 실습 코드는 Document 리스트를 `index()`에 넣는 부분만 보여줌 — 로더/분할기 결합 함수 코드는 없음)
  - **증분 갱신(Incremental Indexing)**: 문서 해시 비교로 신규/변경 문서만 반영 → 임베딩 비용·DB I/O 절감
  - **SQLRecordManager** = source와 내용 해시를 기록하는 "작업 장부"; `index()`가 add / update / skip / delete 결정
- **사용 기술**
  - `from langchain_classic.indexes import SQLRecordManager, index`
  - `SQLRecordManager(namespace="pgvector/integrated_university_rules", db_url=connection_url)` → `.create_schema()`
  - `index(docs_source=docs, record_manager=rm, vector_store=vs, cleanup="incremental", source_id_key="source")`
  - PGVector `collection_name="integrated_university_rules"`, `use_jsonb=True`
  - 결과: 1차 `{'num_added': 2, 'num_updated': 0, 'num_skipped': 0, 'num_deleted': 0}` → 2차(도서관 규정만 변경) `{'num_added': 1, 'num_skipped': 1, 'num_deleted': 1, ...}`
- **환경**: `uv add ipykernel langchain langchain-core langchain-community langchain-classic langchain-openai langchain-postgres "psycopg[binary,pool]" python-dotenv pymupdf`; `.env` 2-5와 동일 (record manager도 같은 `DATABASE_URL` 사용); 노트북 `practice_indexing_pipeline.ipynb`
- **대표 코드**
  ```py
  record_manager = SQLRecordManager(namespace="pgvector/integrated_university_rules",
                                    db_url=connection_url)
  record_manager.create_schema()
  result = index(docs_source=documents, record_manager=record_manager, vector_store=vector_store,
                 cleanup="incremental", source_id_key="source")   # 중복 판별 기준 메타데이터 키
  ```
- **주의/권장**: 매번 전체 재색인 금지(비용·I/O 병목). `cleanup="incremental"`은 같은 source의 구버전 청크를 제거 후 새 청크로 교체. 모든 Document에 `source` 메타데이터 필수(source_id_key). namespace 관례 `"pgvector/<collection_name>"`. 교안 3.2절 코드 블록이 중복 게재됨(내용 동일)

### 강의 간 불일치·교안 오류

1. **"의미론적 분할" 정의 불일치**: 1-5는 인접 문장 임베딩 유사도의 Breakpoint 기반 분할(코드 없음)로 설명, 2-3은 `RecursiveCharacterTextSplitter`의 `separators` 지정을 "의미론적 분할"이라 부름. 2-3의 separators 주석은 "마침표 공백"이라 하나 실제 리스트는 `"."`(공백 없음)
2. **2-3 본문 vs 코드**: 본문은 "중대형 크기(180자)"라 쓰고 코드는 `chunk_size=380`

4. **2-4 `langchain-classic` 설치 누락**: 사용 프로그램 목록·import엔 있으나 `uv add` 명령엔 없음 (2-7에선 포함)
5. **2-6 오타**: `cd chapter02-4`(→ `chapter02-6`), `user_question` 정의 줄 깨짐
6. **노트북 위치 불일치**: 1-3, 1-6, 2-2, 2-3, 2-6은 `src/chapter0X_Y/` 안, 나머지는 프로젝트 루트
