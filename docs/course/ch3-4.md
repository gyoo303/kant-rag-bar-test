## 3장: 기본 RAG 파이프라인 구현

### 3-1. Retriever 구성과 질의 임베딩
- **핵심 개념**
  - 질의 임베딩(Query Embedding): 질문을 문서와 *동일한 임베딩 모델*로 고차원 벡터로 변환
  - 검색기(Retriever): 질의 → 관련 Document 리스트를 반환하는 표준 인터페이스
  - Top-k(`search_kwargs={"k": ...}`): 반환 문서 수 제한
  - LCEL로 Retriever → Format → Prompt → LLM → Parser 연결
- **사용 기술**
  - `from langchain_openai import OpenAIEmbeddings`, `from langchain_postgres.vectorstores import PGVector`
  - `embeddings_model.embed_query(text)` → 1536차원 리스트
  - `vector_store.as_retriever()` / `as_retriever(search_kwargs={"k": 1})`, `retriever.invoke(query)`
  - 컬렉션: `integrated_university_rules` (이전 강 인덱싱 결과 재사용)
  - `ChatPromptTemplate.from_messages`, `StrOutputParser`, `RunnablePassthrough` (모두 `langchain_core`)
  - 기본 k값은 교안에 명시 없음(예시 출력은 `as_retriever()` 기본 호출 시 2건 반환)
- **구조**: 노트북 `src/chapter03_1/practice_retriever.ipynb`
- **대표 코드**
  ```py
  custom_retriever = vector_store.as_retriever(search_kwargs={"k": 1})
  def format_docs(docs): return "\n\n".join(d.page_content for d in docs)
  rag_chain = ({"context": custom_retriever | format_docs, "question": RunnablePassthrough()}
               | prompt | model | StrOutputParser())
  rag_chain.invoke("도서관 대출 권수와 기간 규정을 알려줘.")
  ```
- **프롬프트**: system = "당신은 대학 학사 규정 안내 도우미입니다. 제공된 [참고 문서]에만 근거하여 답변하고, 문서에 없는 내용은 지어내지 마세요. [참고 문서]:\n{context}", user = "{question}"
- **강조점**: temperature=0으로 일관성 확보, gpt-5-mini는 비용 효율 모델로 선정

### 3-2. 벡터 검색 실행·결과 분석
- **핵심 개념**
  - `similarity_search_with_score()`로 `(Document, score)` 튜플 획득
  - PGVector 기본 점수 = **코사인 거리**(1 − 코사인 유사도) → **0에 가까울수록 유사**
  - 네거티브 테스트(Out-of-Domain 질문)로 점수 변동 관찰 → 임계값 기준 도출
- **사용 기술**: `vector_store.similarity_search(query, k)` (문서만), `vector_store.similarity_search_with_score(query=..., k=3)`; 컬렉션 `integrated_university_rules`
- **점수 구간(교안 기준)**: 우수 0.0~0.35 / 보통 0.35~0.60 / 주의 0.60 초과(노이즈 가능성)
- **구조**: `src/chapter03_2/practice_search_analysis.ipynb`
- **대표 코드**
  ```py
  for rank, (doc, score) in enumerate(vector_store.similarity_search_with_score(query=q, k=3), 1):
      print(rank, f"{score:.4f}", doc.page_content, doc.metadata)
  ```
- **강조점 / 검색 실패 체크리스트**
  - 무관한 질문도 상위 k개는 무조건 반환됨(대신 거리 점수가 크게 상승, 예: 0.91)
  - 1순위 거리 ≥ 0.6 → 해당 지식 문서 누락 여부 확인
  - 엉뚱한 문서 상위 노출 → 청크가 너무 길어 주제가 섞였는지 검토
  - 동음이의어 왜곡 → 질문 문장 구조 재점검

### 3-3. Top-k 설정과 score threshold
- **핵심 개념**
  - Top-k 트레이드오프: 크면 노이즈·토큰 비용↑, 작으면 근거 누락→환각
  - **권장 k: 단답형 2~3, 종합 분석형 4~6**
  - Score Threshold: 거리 점수가 임계값보다 **큰** 문서는 탈락(Filter-out)
  - 통과 문서 0건이면 LLM 호출 없이 "정보 없음" 안내(문맥 정제, Context Pruning)
- **사용 기술**
  - `similarity_search(query, k=2)`, `similarity_search_with_score(query, k=3)`
  - **임계값은 retriever 옵션이 아니라 수동 필터**: `SCORE_THRESHOLD = 0.60`, `score <= threshold` 통과
  - `search_type` / `score_threshold` retriever 파라미터는 교안에서 사용하지 않음
  - `from langchain_core.messages import SystemMessage, HumanMessage` 로 메시지 직접 구성 후 `model.invoke(messages)` → `response.content`
- **구조**: 노트북이 프로젝트 루트 `practice_search_tuning.ipynb`
- **대표 코드**
  ```py
  def retrieve_and_generate(user_query: str, k: int = 3, threshold: float = 0.60):
      docs_and_scores = vector_store.similarity_search_with_score(user_query, k=k)
      valid_docs = [d for d, s in docs_and_scores if s <= threshold]
      if not valid_docs:
          return "제공된 규정 문서 내에서 질문과 관련된 내용을 찾을 수 없습니다."
      context_text = "\n\n".join(f"- {d.page_content}" for d in valid_docs)
      messages = [SystemMessage(content="... [참고 문서]\n" + context_text), HumanMessage(content=user_query)]
      return model.invoke(messages).content
  ```
- **프롬프트**: "당신은 대학 규정 안내 AI 비서입니다. 반드시 아래 제공된 [참고 문서]의 내용만을 근거로 정확하게 답변하세요."
- **주의**: 이 페이지의 "학습 목표" 블록은 Streamlit 관련 문구(복붙 오류로 보임)로, 본문 내용과 불일치

### 3-4. 메타데이터 필터링 검색
- **핵심 개념**
  - 메타데이터 = 문서의 "이름표"(연도, 카테고리, 대상자 등), PGVector는 JSONB로 저장
  - 사전 필터링(Pre-filtering): 벡터 거리 계산 전 조건 미충족 문서 제외 → 정확도·효율↑
  - 의미만으로는 2023/2024 규정처럼 비슷한 문장의 구 버전을 오답으로 가져올 위험
  - 복합 필터(Composite Filter): 여러 키 동시 일치
- **사용 기술**
  - `from langchain_core.documents import Document`; `Document(page_content=..., metadata={...})`
  - `vector_store.add_documents(sample_rules)`
  - 필터 문법: `filter={"category": "scholarship", "year": 2024, "target": "undergraduate"}` (딕셔너리 나열 = AND)
  - `vector_store.similarity_search(query=..., k=2, filter=target_filter)`
  - 컬렉션: `metadata_university_rules`
- **구조**: 루트 `practice_metadata_filter.ipynb`
- **대표 코드**
  ```py
  def generate_rag_answer(user_query: str, search_filter: dict = None, k: int = 2):
      docs = (vector_store.similarity_search(query=user_query, k=k, filter=search_filter)
              if search_filter else vector_store.similarity_search(query=user_query, k=k))
      if not docs: return "조건에 일치하는 관련 규정을 찾을 수 없습니다."
      context_text = "\n\n".join(d.page_content for d in docs)
      # SystemMessage("당신은 대학 행정 규정 안내 비서입니다. ... [참고 문서]\n{context_text}") + HumanMessage
  ```
- **강조점**: 구 버전 문서가 모델 입력에 들어가는 것을 원천 차단해야 연도 왜곡 없는 답변

### 3-5. 검색 문맥 주입 프롬프트 설계
- **핵심 개념**
  - 문맥 주입(Context Injection): 외부 지식 강제 + 답변 범위 한정으로 환각 제어
  - RAG 프롬프트 3요소: 시스템 역할·지침(System) / 참고 문맥(Context) / 사용자 질문(Question)
  - 문맥 포맷팅: 문서 번호 + 빈 줄 구분
  - Lost in the Middle: 긴 프롬프트의 중간 정보 누락 현상
- **사용 기술**
  - `ChatPromptTemplate.from_messages([...])`, 중괄호 `{context}`, `{question}` 변수 슬롯
  - LCEL: `rag_chain = prompt_template | model | StrOutputParser()` → `invoke({"context": ..., "question": ...})`
  - DB 없이 `Document` 리스트를 직접 만들어 실습
- **구조**: 루트 `practice_prompt_template.ipynb`
- **대표 코드 (표준 format_docs)**
  ```py
  def format_docs(docs: list[Document]) -> str:
      return "\n\n".join(f"[문서 {i}]\n{d.page_content}" for i, d in enumerate(docs, 1))
  ```
- **표준 system 문구**: "당신은 대학 행정 규정 안내 비서입니다.\n반드시 아래 제공된 [참고 문서] 내용만을 근거로 정확하게 답변하세요.\n문서에 근거가 없는 내용은 절대 추측하지 말고 '제공된 규정에서 확인할 수 없습니다.'라고 답변하세요.\n\n[참고 문서]\n{context}"
- **컨텍스트 길이 관리 권장**: 주입 문서 수 2~3개로 엄격 제한, 불필요한 공백·중복 텍스트·메타데이터 정제 후 주입
- **주의(교안 결함)**: 이 강의 템플릿에는 `("human", "{question}")` 메시지가 **빠져 있어** 질문이 모델에 전달되지 않음(예시 출력도 질문에 답하지 않고 "질문하실 내용을 알려주시면…"으로 응답). 3-6에서 human 메시지가 추가된 형태가 정상형.

### 3-6. 검색→생성 체인 통합
- **핵심 개념**
  - LCEL 데이터 파이프라인: 단일 질문 입력을 분기 → 병합
  - 문맥 생성 경로: `retriever | format_docs` → `{context}`
  - 질문 유지 경로: `RunnablePassthrough()` → `{question}`
  - 파이프 연산자 `|`로 엔드투엔드 통합 체인
- **사용 기술**
  - `from langchain_postgres import PGVector` (3-1~3-4는 `langchain_postgres.vectorstores`)
  - 컬렉션 `university_regulations`, `add_documents` 후 `as_retriever(search_kwargs={"k": 2})`
  - `ChatPromptTemplate`(system + `("human", "{question}")`), `StrOutputParser`
- **구조**: 루트 `practice_rag_chain.ipynb`
- **대표 코드**
  ```py
  retriever = vector_store.as_retriever(search_kwargs={"k": 2})
  rag_chain = (
      {"context": retriever | format_docs, "question": RunnablePassthrough()}
      | prompt_template | model | StrOutputParser()
  )
  rag_chain.invoke("학부생 전액 장학금 기준과 지급 방식은 어떻게 되나요?")
  ```
- **강조점**: temperature=0 → 무작위성 최소화, 문맥 기반 사실 응답

### 3-7. 출처 표기·응답 후처리
- **핵심 개념**
  - 메타데이터(꼬리표)를 파이프라인 끝까지 보존해 출처 표기
  - 데이터 분기 보존: 프롬프트용 텍스트(`context`)와 원본 문서(`source_documents`)를 별도 유지
  - 후처리(Post-processing): "생성 답변"과 "출처 리스트"를 분리해 보기 좋게 출력
- **사용 기술**
  - 컬렉션 `university_scholarship`, `as_retriever(search_kwargs={"k": 2})`
  - 순수 LCEL dict 대신 **일반 파이썬 함수**로 검색·분기 후 `generation_chain = prompt_template | model | StrOutputParser()` 호출
  - 프롬프트: system "당신은 대학 행정 비서입니다.\n반드시 아래 제공된 [참고 문서] 내용만을 근거로 정확하게 답변하세요.\n\n[참고 문서]\n{context}" + human "{question}"
- **구조**: 루트 `practice_source.ipynb`
- **대표 코드**
  ```py
  def retrieve_and_format(question):
      docs = retriever.invoke(question)
      return {"question": question, "source_documents": docs, "context": format_docs(docs)}
  def final_post_processing(question):
      inputs = retrieve_and_format(question)
      answer = generation_chain.invoke(inputs)
      print("[AI의 답변]\n" + answer + "\n\n[참고한 출처]")
      for i, d in enumerate(inputs["source_documents"], 1):
          print(f"{i}. 카테고리: {d.metadata.get('category','분류 없음')} (제정 연도: {d.metadata.get('year','연도 미상')}년)")
  ```
- **출처 표기 방식(교안 정의)**: 답변 본문 뒤에 `[참고한 출처]` 섹션, 번호 목록 `N. 카테고리: {category} (제정 연도: {year}년)`; 메타데이터 누락 시 기본값 "분류 없음"/"연도 미상". LLM에게 출처를 쓰게 하지 않고 **시스템이 보존한 메타데이터로 출력**.
- **강조점**: 학습 목표상 "답변에 참고 문서 출처(메타데이터)를 정확히 표기", 2.2에서 `RunnablePassthrough`로 분기한다고 설명하지만 실제 코드는 함수 기반 분기

## 4장: 검색 고도화 이론

> 4장 `.env`는 `OPENAI_API_KEY`만 사용(DB 미사용). PGVector 대신 인메모리/로컬 계산으로 실습.

### 4-1. 키워드 검색 vs 벡터 검색
- **핵심 개념**
  - 키워드 검색(BM25): 단어 등장 빈도 기반, "컴퓨터"로 "PC" 문서 못 찾음
  - 벡터 검색(Semantic Search): 의미 유사도 기반
  - 적합 상황: 정확한 단어(부서명·연도·부품번호) → 키워드 / 분위기·의미 → 벡터
- **사용 기술**
  - 설치: `uv add ipykernel langchain langchain-core langchain-openai python-dotenv rank_bm25`
  - `from rank_bm25 import BM25Okapi`, `numpy`(`np.argmax`, `np.dot`)
  - 토큰화: `doc.split(" ")` (공백 기준), `bm25.get_scores(tokenized_query)`
  - `embeddings_model.embed_documents(documents)`, `embed_query(query)`, 내적(dot)으로 유사도
- **구조**: `chapter04-1/`, 루트 `practice_search.ipynb`
- **대표 코드**
  ```py
  bm25 = BM25Okapi([d.split(" ") for d in documents])
  best_bm25 = np.argmax(bm25.get_scores(query.split(" ")))
  doc_vectors = embeddings_model.embed_documents(documents)
  qv = embeddings_model.embed_query(query)
  best_vec = np.argmax([np.dot(qv, v) for v in doc_vectors])
  ```
- **주의(교안 불일치)**: 코드 주석은 "키워드 검색은 엉뚱한 결과"라고 하지만 예시 출력은 두 방식 모두 아이폰 문서를 1위로 표시(점수가 모두 0이면 argmax가 0번 문서를 반환하는 것으로 보임 — 교안 설명은 없음)

### 4-2. Hybrid Search
- **핵심 개념**
  - 하이브리드 검색 = 키워드(BM25: 고유명사·일련번호·날짜) + 벡터(동의어·오타·뉘앙스) 결합
  - 결합 방식: 가중합(Weighted Sum) `최종 = 키워드×0.3 + 벡터×0.7`
  - RRF(Reciprocal Rank Fusion): 순위 기반 합산 `1 / (순위 + 60)` — 점수 척도 차이 제거
- **사용 기술**
  - 설치: `uv add ipykernel langchain langchain-core langchain-community langchain-classic langchain-openai python-dotenv rank_bm25`
  - `from langchain_community.retrievers import BM25Retriever` → `BM25Retriever.from_documents(docs)`, `bm25_retriever.k = 2`
  - `from langchain_core.vectorstores import InMemoryVectorStore` → `.from_documents(docs, embeddings_model).as_retriever(search_kwargs={"k": 2})`
  - `from langchain_classic.retrievers import EnsembleRetriever` → `EnsembleRetriever(retrievers=[bm25, vector], weights=[0.3, 0.7])`
  - 생성: f-string 프롬프트 + `model.invoke(prompt)` → `.content`
- **구조**: 루트 `practice_hybrid.ipynb`
- **대표 코드**
  ```py
  hybrid_retriever = EnsembleRetriever(retrievers=[bm25_retriever, vector_retriever], weights=[0.3, 0.7])
  docs = hybrid_retriever.invoke(query)
  context = "\n\n".join(f"- {d.page_content}" for d in docs)
  prompt = f"다음 문서를 참고하여 질문에 명확하고 친절하게 답변하세요.\n\n[참고 문서]\n{context}\n\n[질문]\n{query}"
  model.invoke(prompt).content
  ```
- **참고**: 각 검색기 k=2라도 앙상블 결과는 합집합(예시 출력 3건)

### 4-3. Re-ranking
- **핵심 개념**
  - 2단계 검색(2-Stage Search): 1단계 Retrieval(Top-N, 보통 10~30개, 키워드/벡터/하이브리드) → 2단계 Re-ranking(Top-K, 보통 2~5개)
  - Bi-Encoder: 질문·문서 독립 벡터화, 빠름(1차 검색용)
  - Cross-Encoder: `[질문 + 문서]` 쌍을 동시 입력, 정확하지만 느림 → 1차 결과 소수에만 적용
- **사용 기술**
  - 설치: `uv add ipykernel langchain langchain-core langchain-community langchain-classic langchain-openai python-dotenv sentence-transformers`
  - `from sentence_transformers import CrossEncoder`; 모델 **`"Dongjin-kr/ko-reranker"`**
  - `reranker_model.predict([[query, doc], ...])` → 점수(높을수록 밀접), `sorted(..., reverse=True)`
  - 재정렬 1위 문서만 문맥으로 사용해 f-string 프롬프트 → `model.invoke`
- **구조**: 루트 `practice_rerank.ipynb` (`.env`는 OpenAI 키만)
- **대표 코드**
  ```py
  reranker_model = CrossEncoder("Dongjin-kr/ko-reranker")
  scores = reranker_model.predict([[query, d] for d in documents])
  ranked = sorted(zip(documents, scores), key=lambda x: x[1], reverse=True)
  top_doc = ranked[0][0]
  ```
- **강조점**: Re-ranking으로 정답에 가까운 문서를 상위 배치 → 환각 감소·생성 품질 향상
- **참고**: 이 강의의 프롬프트("명확하고 친절하게")는 "문서 외 추측 금지" 제약이 없어 예시 답변이 문서 밖 내용을 다수 포함함(교안은 별도 언급 없음)

### 4-4. Query 변환 기법
- **핵심 개념**
  - Query 변환(Query Transformation) = 검색 전단계(Pre-Retrieval) 최적화: 어휘 불일치 해소, 모호성 제거(오타·축약어·대명사), 1차 검색 실패 선제 차단
  - **교안의 4대 기법** (Multi-Query는 다루지 않음):

    | 기법 | 핵심 동작 | 적용 시나리오 |
    | --- | --- | --- |
    | Query Rewrite (질문 재작성) | 맞춤법 교정, 핵심 명사 중심 재구성 | 질문이 너무 짧거나 은어·오타 |
    | HyDE (가설 문서 임베딩) | 가상의 예상 답변 문서를 먼저 생성 → 그것을 임베딩해 검색 | 질문과 정답 문서 간 문체·전문성 격차 큼 |
    | Query Routing (질문 라우팅) | 질문 성격 판별 → 저장소 경로 지정 | 복수 저장소(문서 벡터DB, SQL, 웹) |
    | Memory 기반 검색 (대화 맥락 반영 / Contextualization) | 직전 대화로 대명사·생략 복원 → 독립 질문화 | 멀티턴 챗봇 |
- **사용 기술**
  - 설치: `uv add ipykernel langchain langchain-core langchain-community langchain-openai python-dotenv`
  - `from langchain_core.prompts import PromptTemplate` → `PromptTemplate.from_template(...)`
  - 체인: `prompt | model` (파서 없이 `.content` 사용), 모두 gpt-5-mini, temperature=0
  - 라우팅 대상 라벨: `[사내규정_벡터DB, 매출실적_SQL, 최신동향_웹검색]`, 결과 `.content.strip()`
  - 메모리: 변수 `{chat_history}`, `{question}`; history는 "사용자: ...\nAI: ..." 문자열
- **구조**: 루트 `practice_query_transform.ipynb`
- **대표 프롬프트(요지)**
  - Rewrite: "사용자의 질문을 검색 시스템이 문서를 탐색하기 유리하도록 핵심 명사 중심의 명확한 문장으로 다시 작성하세요.\n사용자 질문: {question}\n변환된 질문:"
  - HyDE: "다음 질문에 대한 객관적인 사실을 서술하는 한 단락의 학술적 답변을 작성하세요.\n질문: {question}\n가설 답변:"
  - Routing: "질문을 읽고 다음 3가지 저장소 중 가장 적절한 대상을 하나만 선택하여 단어로 출력하세요: [...]\n질문: {question}\n선택된 저장소:"
  - Memory: "이전 대화 내용을 바탕으로 현재 질문에 생략된 맥락과 대명사를 복원하여 완전한 단일 검색 질문으로 재작성하세요.\n[이전 대화]\n{chat_history}\n[현재 질문]\n{question}\n복원된 질문:"
- **대표 코드**
  ```py
  rewrite_chain = PromptTemplate.from_template(REWRITE_TMPL) | model
  rewritten = rewrite_chain.invoke({"question": raw_query}).content
  memory_chain = PromptTemplate.from_template(MEMORY_TMPL) | model
  q = memory_chain.invoke({"chat_history": history, "question": follow_up}).content
  ```
- **주의**: 교안 코드는 변환 결과만 출력하고 실제 검색기 연결은 하지 않음. Memory 예시 출력에 "복원된 질문:" 접두어가 그대로 섞여 나옴(후처리 필요성 시사, 교안 언급 없음). HyDE 프롬프트 원문에 오타("한 달락").

## 3·4장 공통 스택 요약

**스택(한 줄)**: Python 3.13 + uv / LangChain(`langchain`, `langchain-core`, `langchain-community`, `langchain-classic`) + `langchain-openai` + `langchain-postgres`(PGVector, psycopg3, `use_jsonb=True`) / 임베딩 `text-embedding-3-small` / LLM `gpt-5-mini`(`init_chat_model`, temperature=0) / 고도화: `rank_bm25`·`BM25Retriever`·`EnsembleRetriever`(0.3/0.7)·`sentence-transformers` CrossEncoder `Dongjin-kr/ko-reranker` / `.env`: `OPENAI_API_KEY`, `DATABASE_URL` / 버전 고정 없음.

**표준 RAG 프롬프트 (3-5/3-6 정상형)**
```py
ChatPromptTemplate.from_messages([
  ("system", "당신은 대학 행정 규정 안내 비서입니다.\n"
             "반드시 아래 제공된 [참고 문서] 내용만을 근거로 정확하게 답변하세요.\n"
             "문서에 근거가 없는 내용은 절대 추측하지 말고 '제공된 규정에서 확인할 수 없습니다.'라고 답변하세요.\n\n"
             "[참고 문서]\n{context}"),
  ("human", "{question}"),
])
```

**표준 체인 구조**
```
질문 ─┬─ retriever(k=2) | format_docs("[문서 i]\n본문", "\n\n" 결합) → {context}
      └─ RunnablePassthrough() → {question}
   → prompt_template → model(gpt-5-mini, T=0) → StrOutputParser()
출처 필요 시(3-7): 함수로 {question, source_documents, context} 분기 → generation_chain 실행 → 메타데이터로 [참고한 출처] 출력
품질 제어: 거리 점수 threshold 0.60 수동 필터(0건이면 "찾을 수 없습니다" 반환), metadata filter dict(AND), k 2~3
고도화: Query 변환(Rewrite/HyDE/Routing/Memory) → Hybrid(BM25+Vector, EnsembleRetriever) Top-N → Cross-Encoder Re-rank Top-K → 생성
```

**강의 간 불일치/주의점**
1. PGVector import 경로: 3-1~3-4 `langchain_postgres.vectorstores.PGVector` vs 3-6/3-7 `langchain_postgres.PGVector`.
2. 컬렉션 이름이 강의마다 다름: `integrated_university_rules`(3-1~3-3), `metadata_university_rules`(3-4), `university_regulations`(3-6), `university_scholarship`(3-7).
3. 생성 방식 혼재: LCEL 체인(3-1, 3-5, 3-6, 3-7 일부) vs `SystemMessage/HumanMessage` 직접 호출(3-3, 3-4) vs f-string 프롬프트 + `model.invoke`(4-2, 4-3) vs `PromptTemplate | model`(4-4).
4. 프롬프트 human 슬롯: 3-1은 `"user"`, 3-6/3-7은 `"human"` 역할명 사용; 3-5는 `{question}` 메시지 자체 누락(결함).
5. format_docs: 3-1은 단순 `"\n\n".join`, 3-5 이후는 `[문서 i]` 번호 포함, 3-3/4-2는 `- ` 불릿 형식.
6. Score threshold는 retriever의 `search_type="similarity_score_threshold"`가 아니라 `similarity_search_with_score` 결과를 코사인 **거리** 기준(`<=`)으로 수동 필터. 거리 vs 유사도 방향 혼동 주의.
7. 노트북 위치: 3-1/3-2는 `src/chapterXX_N/` 안, 3-3 이후는 프로젝트 루트.
8. 4-3/4-4 "사용 프로그램"은 Python 버전 미기재(단 `uv init`은 3.13), 4-3 목록엔 없지만 설치 명령엔 `langchain-classic` 포함.
9. 3-3 학습 목표가 Streamlit 내용(복붙 오류), 4-1 키워드 검색 예시 출력이 주석 설명과 불일치.
10. 4-2/4-3 생성 프롬프트에는 "문서 외 추측 금지" 제약이 없음 — 3장 표준 프롬프트와 다름.
11. Multi-Query 기법은 4-4에 포함되지 않음.
