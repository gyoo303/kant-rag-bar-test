# 법률 도메인 RAG 에이전트 — 논문·발표용 정리 노트

> 변호사시험 민사법 선택형을 푸는 근거 기반 RAG 에이전트 (칸트냥이 팀 · RAG 에이전트 2 · 서상혁)
> 작성 2026-11-27 · 저장소 `gyoo303/kant-rag-bar-test` (`sanghyuk`, `verify-2022` 브랜치)
>
> 이 문서는 논문의 뼈대로 쓰기 쉽게 **주장 → 근거 수치 → 출처 파일** 순서로 정리했다. 기업이 눈여겨볼 지점은 ★ 로 표시했다.
> 모든 수치는 1회 실행, 정답가안 기준이다 (한계는 9장).

---

## 0. 한 줄 요약 (Abstract 초안)

변호사시험 민사법 선택형 문항을, LLM 이 정답 번호를 고르지 않고 **진술마다 판례·조문 근거로 참/거짓을 판단한 뒤 규칙으로 정답을 계산**하는 RAG 에이전트로 풀었다.
- 처음 보는 시험(제13회)에서 70문항 중 65문항을 맞혔다. 같은 모델이 근거 없이(closed-book) 풀면 53문항이다.
- 근거가 확정된 30문항에서 정답 근거 검색 Recall@5 를 87.4% → 97.8% 로 올렸다.
- 검증한 모든 실행에서 **인용 없이 단정한 판단은 0건**이었다.
- 레드팀 변형본에서는 시험 시점 색인으로 30/30 이었다. 최신 색인에서는 개정 조문 공략에 5문항을 잃어, **법령 시점 관리**가 법률 RAG 의 핵심 과제임을 보였다.

| 과제 | 변호사시험 민사법 선택형 (민법·상법·민사소송법), 문항당 지문 4~5개, 70문항 |

## 3. 시스템 (Method)

```
데이터 준비 → 문제 입력 → 검색(진술마다) → 판단 → 정답 → 평가·개선
```
(Mermaid 흐름도: 노션 '프로젝트 로직 플로우차트', 단계별 그림: `docs/media/v6r2-walkthrough.mp4`)

| 단계 | 구성 요소 | 도입 버전 |
|---|---|---|
| 입력 | 진술 분리, 형식·극성 판정('판례의 태도와 다른 것' = 옳지 않은 것), 기준 시점 추출 | v2, v6r2 보강 |
| 질의 | LLM 리라이트(쟁점·예외·당사자 지위) + **진술 원문 질의** + 진술 간 참조 질의 | v3~v5 |
| 검색 | BM25 + 벡터 → RRF → 리랭커, 기준일 뒤 판례 제외, 원문 질의 상위 결과 보장 | v2, v5, v6r2 |
| 근거 확장 | 같은 판결 다른 항목, 준용 조문(정·역방향), **연결 지도**(판례 변경·참조판례·참조조문), 조문 위치·제목 | v3, v6 |
| 판단 | 진술 평서문화(이중부정 해소), 참/거짓/유보 + 확신도 + 인용 문장 + stance | v4~v7 프롬프트 |
| 검증 | 인용 원문 대조, 근거 적합성(리랭커), 인용-결론 일치, 답과 어긋난 고확신 진술 | v5, v6r2 |
| 재탐색 | 유보·저확신·불일치 진술만 2차 검색 → 재판단 (인용 확인 + 확신도 비감소일 때만 채택) | v6 |
| 결정 | 보기 점수 = 진술 판단의 곱 → 최고점. 동점이면 해당 진술 재판단·다수결 | v2, v4~v6r2 |

**설계 원칙**: 새 기능은 모두 설정 스위치(`mcq.*`)이고 프리셋(`v2`~`v6r2`)으로 묶는다. 이전 프리셋의 동작은 바꾸지 않는다(회귀 테스트로 확인).

## 4. 평가 방법 ★

| 구성 | 내용 |
|---|---|
| 시험 세트 | 제13회(bar13, 처음 보는 시험) · 2026 시험 · 제12회 레드팀 변형본 · 제11회(2022) 근거 확정 30문항 · 그 레드팀 변형본 v2 |
| 시점 통제 | 2022 검증 브랜치: 2022. 1. 1. 시행 법령 스냅숏 + 2022. 1. 10. 까지 선고 판례로 색인을 따로 만듦 (미래 정보 차단) |
| 정답 근거(gold) | 지문마다 결정적 근거 판례·조문 (30문항 139지문 · 142근거). 판례는 사건번호, 조문은 '법령명 제N조' 단위로 일치 판정 |
| 3파트 지표 | **검색** Recall/Hit/Precision@k·MRR · **사실** Context Recall/Precision, 인용 Recall/Precision · **답변** 문항·지문 정답률, 확신 오답 |
| 지문 A~E | A 정답+정답 근거 인용 · B 정답·다른 문서 인용 · C 근거 있는데 오판 · D 근거 없이 오판 · E 유보 |
| 추론 개입 | 인용 없이 단정한 판단, 정답 근거가 입력에 없는데 맞힌 지문, closed-book 대비 |
| 레드팀 | 공략 축 A 조문 시점 · B 판례 시점 · C 옛 법리 미끼 · D 보기 배치 · E 색인 밖 시행령 · F 발문 극성·형식 |

## 5. 주요 결과

### 5.1 RAG vs closed-book (같은 모델·같은 판단 형식)

| 시험 | RAG | closed-book | 차이 | 출처 |
|---|---|---|---|---|
| 제13회 (처음 보는 시험) | **65/70** (v3) | 53/70 | +12 | `report-bar13-v3.md` |
| 2026 | 58/70 (v2) | 40/70 | +18 | 같은 문서 |
| 제13회 진술 단위 | 312 정답 / 11 오답 | 275 / 48 | 오답 −77% | 같은 문서 |

### 5.2 근거 확정 30문항 (2022 시점 색인)

| 지표 | v2 | **v6** | 변화 |
|---|---|---|---|
| 문항 정답 | 29/30 | 29/30 | = |
| 검색 Recall@5 · MRR | 87.4% · 0.760 | **97.8% · 0.853** | +10.4%p |
| Context Recall | 87.1% | 97.8% | +10.7%p |
| 인용 Recall · Precision | 81.3% · 75.0% | 89.2% · 82.4% | +7.9 · +7.4%p |
| 지문 A (근거 기반 정답) | 77.7% | 88.5% | +10.8%p |
| **모든 지문이 A 인 문항** | 10/30 | **16/30** | +6 |
| 유보 / 확신 오답 | 14 / 0 | 0 / 2 | 단정 증가의 대가 |
| 인용 없이 단정한 판단 | 0 | 0 | — |
| 문항당 시간 | 16초 | 38초 | ×2.4 |

★ **핵심 관찰**: 문항 정답률(96.7%)은 근거 품질(완전 근거 정답 33% → 53%)보다 훨씬 높게 나온다. 선택형은 지문 하나를 유보해도 답이 정해지기 때문이다. **정답률만 보는 평가는 RAG 품질을 과대평가한다.**

## 7. 기업이 눈여겨볼 포인트 (Industry takeaways) ★

1. **"LLM 이 답을 고르지 않게 하라."** LLM 은 근거 대조만 하고 결정은 규칙으로 하면 감사 가능성, 오류 원인 분리, 형식 공격 내성을 동시에 얻는다. 규제 산업(법무·금융·의료)의 의사결정 보조에 바로 적용된다.
2. **데이터 구조에 먼저 투자하라.** 판결요지처럼 "한 덩어리 = 한 규칙"으로 정리된 원자료가 검색 성능의 9할을 설명했다. 사내 문서도 규칙·조항 단위 구조화가 모델 교체보다 효과가 크다.
3. **시점(as-of)은 1급 요구사항이다.** 최신 색인 하나로는 과거 기준 질문을 정확히 풀 수 없었다 (30 → 25). 문서 버전·시행일 메타데이터와 시점별 색인이 필요하다.
4. **정답률이 아니라 근거 품질로 평가하라.** 정답률 96.7% 시스템의 완전 근거 정답은 33~53% 였다. 지문 단위 gold·A~E 분류·추론 개입 지표가 실제 신뢰도를 보여 준다.
5. **"모름"과 "확신 오답" 사이의 트레이드오프를 설계하라.** v2 는 유보 14·확신 오답 0, v6 는 유보 0·확신 오답 2였다. 운영에서는 동점·저확신·불일치를 사람 검토 대상으로 표시하는 정책이 필요하다.
6. **검증 비용은 의심 지점에만.** 2차 검색·재판단을 의심 진술에만 돌려 시간 증가를 제한했다 (그래도 v2 대비 ×2.4 — 비용·지연 관리가 실서비스 과제).
7. **레드팀은 블라인드로.** 공략안을 보고 방어를 만든 뒤 같은 공략으로 시험하면 견고성이 과대평가된다 (bar12 변형본에서 확인). 방어 쪽이 공략안을 모르는 평가가 필요하다.
8. **정답표도 틀린다.** 원문 대조로 레드팀 정답표 오류 3건을 찾았다. 평가 데이터 자체의 검증 절차가 필요하다.

## 9. 한계 (Limitations)

- **1회 실행**: LLM 판단은 실행마다 변한다. 1~2문항 차이는 변동 범위 안이다 (`eval --repeat 3` 필요).
- **정답가안 기준**: 제11회는 확정 정답 발표 전 정답가안으로 채점했다.
- **정답 근거의 편향**: 근거 확정 30문항은 한 에이전트 색인의 검색 후보에서 골라 확정해, 검색이 쉬운 문항 쪽으로 치우쳤을 수 있다.
- **사후 방어**: 레드팀 축 F(발문 극성·형식) 방어는 변형본을 본 뒤 고쳤다. bar12 변형본의 방어도 공략안을 보고 만들었다.
- **모델 지식 누설**: 2022 검증에서 근거는 시점으로 막았지만, 모델이 이후 판례를 학습했을 가능성은 막지 못한다.
- **v6r2 미실측**: v6r2 는 구현·테스트까지 했고, 실제 시험 실행 결과는 아직 없다 (시연 영상의 2차 판단 값은 예시).
- **비교 실험 부족**: 메타데이터·개별 스위치의 효과는 결과와 맞물려 해석했을 뿐, 하나씩 끈 ablation 은 일부만 했다.

1. 기준일 → 그 시점 법령 스냅숏으로 조문 검색 (최신 색인 하나로 과거 기준 문제 해결)

3. 블라인드 레드팀: 판결 이유에만 있는 법리, 판결요지와 다르게 쓴 지문, 색인 밖 하위 법령
4. 시행령·누락 판례 수집, 정답 근거 사람 교차 검토(일치율 보고)
5. 비용·지연 최적화: 판단 입력 축소(`v6r2-lite`), 문항 병렬 처리
