## 요약
- 2026 시험 39 → **50** (+11), 2025 시험 42 → **46** (+4) — LLM 단독 대비, RAG C 구성
- 틀린 44문항 중 33문항이 검색 문제(검색 누락·문맥 부족), 근거는 거의 모두 색인에 있었음

## 구조
| 단계 | 방식 | 코드 위치 (`src/civil_rag/`) |
|---|---|---|
| 데이터 | 팀 판례 42,537건(대법원 출처 민사) + 시험일 기준 법령 18개. 판례는 시험 전날까지 선고분만 사용 | `law_collector/collect.py · ingest/build.py (in_date_range)` |
| 청킹 | 판시사항·판결요지를 원래 항목([1][2], 가.나.) 단위로 한 조각씩. 판결 전문 제외. 참조조문·참조판례는 메타데이터 | `ingest/chunking.py (prec_to_chunks_field, split_items, parse_ref_articles)` |

| 검색 A/B/C | A 벡터 / B BM25+벡터 가중 RRF(0.5:0.5, c=60) / C B 후보 20개를 ko-reranker로 재정렬 → 5개 | `retrieval/pipeline.py (Retriever.retrieve), fusion.py, tokenize.py` |

1. 판결 전문을 빼고 판결요지 항목 단위로만 넣었는데, 상혁님처럼 1,000자 넘는 요지를 문장 단위로 더 나누는 게 나을까요?
2. 리랭커를 교안 모델(ko-reranker)로 유지할지, 팀 설계 문서의 bge-reranker-v2-m3로 바꿀지 같은 시험지로 비교해 볼까요?
3. 지문별 판단을 지문마다 LLM 호출(제 per_choice) vs 한 번에 묶어 호출(상혁님) 중 어느 쪽이 정확도·비용 면에서 나을까요?
4. 폐기된 판례를 표시할 방법(판례 본문의 '변경' 문구, 별도 목록 등) 아이디어가 있나요?
