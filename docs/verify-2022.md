# verify-2022 브랜치 — 2022년 시험 전 판례만으로 검증

> 브랜치 `verify-2022` (sanghyuk 에서 분기, v6 포함). 2022년 변호사시험(제11회, 2022. 1. 11. 시작)을 **그 시점까지 선고된 판례만** 가지고 푼다.

## 이 브랜치에서 바뀐 것 (`configs/default.yaml`)

| 설정 | 값 | 뜻 |
|---|---|---|
| `paths.index_dir` | `index-2022` | 2022 색인을 따로 만든다. 현재 색인 `index/` 는 그대로. 법령 스냅숏이 붙어 실제 폴더는 **`index-2022@20220101/`** |
| `corpus.statute_snapshot` · `law_date` | `20220101` | 법령을 `data/raw/statutes@20220101/` (2022. 1. 1. 시행 버전)에서 읽는다 |
| `corpus.case_date_to` | `20220110` | 색인할 때 이 날짜 뒤 선고 판례 제외 |
| `retrieval.case_date_to` | `20220110` | 검색 단계에서 한 번 더 제외 (안전장치) |
| `mcq.asof_default` | `20220110` | 발문에 기준 시점이 없으면 이 날짜 기준 |
| `mcq.hide_future` | `true` | 이 날짜 뒤 판례는 근거 표시(판례 변경 `overruled_by`)에서도 숨김 |

연결 지도(v6)는 색인에 있는 판례만 잇고, 그 뒤 판례가 붙인 참조판례·참조조문 연결은 색인에 없으므로 쓰이지 않는다.
단위 테스트는 `tests/conftest.py` 가 위 값을 끈 설정으로 돌린다 (`tests/test_verify2022.py` 가 이 브랜치 설정을 확인).

## 2022. 1. 1. 법령 스냅숏 (`data/raw/statutes@20220101/`)

팀이 준 `laws_txt_20220101.zip` (법제처, 2022. 1. 1. 시행 버전) 18개 법령. 파일 이름의 `_` 를 공백으로 바꿔 문서 목록 경로와 맞췄다. 형식(머리줄 2줄 + 편·장·조)은 지금 파서로 그대로 읽힌다.

| 비교 (현재 2026 버전 대비) | 결과 |
|---|---|
| 조문 수가 같은 법령 | 가등기담보법·가사소송법·민사집행법·부동산실명법·어음법·채무자회생법 |
| 내용이 바뀐 조문 (`<개정 …>` 표시 제외) | **92개** — 상법 33, 민법 17, 부동산등기법 11, 채무자회생법 9, 집합건물법 8, 민사소송법 7 등 |
| 2022년 뒤 새로 생긴 조문 (2022 색인에 없음) | 민법 제1004조의2, 민사소송법 제219조의2·제402조의2·제402조의3, 부동산등기법 제7조의2·3, 상법 제614조의2, 상가임대차법 제11조의2, 주택임대차법 제3조의7, 집합건물법 제26조의5 |
| 이번에 새로 들어온 법령 | 수표법·신탁법·약관규제법·이자제한법 (문서 목록에는 있었으나 원문이 없었음), **제조물 책임법** (문서 목록에 `LAW-PRODUCT` 로 추가) |

**스냅숏에 없는 문서**(상법 시행령, 소송촉진법, 보증인보호법, 소액사건심판법, 전자등록법, 공탁법, 사물관할규칙, 민사소송규칙, 민사집행규칙)는 PC 의 **현재 버전**을 쓴다. `build-index` 가 경고를 출력하고 `index_info.json` 의 `snapshot_fallback` 에 기록한다. 시점이 엄밀해야 하면 이 문서들도 2022. 1. 1. 버전을 받아 `statutes@20220101/` 에 넣는다.

색인 머리의 문서 버전은 스냅숏 파일 첫 줄에서 읽는다 (예: 민법 `시행 20210126 (스냅숏 20220101)`).

## 한계
- **LLM(gpt-6-luna)은 2022년 뒤 판례를 학습했을 수 있다.** 근거는 막아도 모델 기억은 막지 못한다. 근거 없이 판단한 진술(`source=knowledge`·인용 없음)을 따로 보아야 한다.

## PC 실행

```
git fetch origin
git checkout verify-2022
git pull
uv run pytest -q
uv run kant-rag build-index
```
- **`index-2022@20220101/`** 에 새 색인을 만든다 (판례 2022. 1. 10. 까지 + 법령 2022. 1. 1. 버전). 앞서 만든 `index-2022/`(현재 법령)는 쓰지 않으니 지워도 된다.
- 판례 청크 36,087개 (현재 기준 39,268개의 92%, 가장 늦은 선고 2021-12-30). GPU 임베딩 수십 분.
- 끝나면 `index-2022@20220101/index_info.json` 에서 `case_date_to` 20220110, `statute_snapshot` 20220101, `snapshot_fallback` 목록을 확인.

시험지·정답은 이미 들어 있다 (`data/exam/bar11_civil.json`, 70문항, 정답가안).

풀기·채점:
```
uv run kant-rag eval data/exam/bar11_civil.json --modes hybrid_rerank --preset v6 --workers 1 --label bar11-v6-2022
uv run kant-rag regrade results/<실행 폴더> --exam data/exam/bar11_civil.json
```

작업이 끝나면 `git checkout sanghyuk` 로 돌아간다 (색인 폴더가 달라 서로 덮어쓰지 않는다).
