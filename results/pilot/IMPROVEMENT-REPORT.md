## 1. 무엇을 만들었나

2026년 변호사시험 선택형 민사법 문항(지문 + 보기 5개)을 입력하면, 민사법 조문과 대법원 민사
판례에서 근거를 검색해 **정답 번호와 보기별 근거를 제시**하는 RAG 에이전트다.

| 구성 요소 | 내용 |
|---|---|
| 말뭉치 | 법령 13개 조문 **4,265**건 + 대법원 민사 판례 **35,831**건 = 문서 40,096건 |
| 색인 | 청크 **54,969**개, PGVector(`text-embedding-3-small`, 1536차원) |
| 검색 | 쿼리 리라이트 → BM25(Kiwi) + 벡터 앙상블(가중 RRF) → CrossEncoder 재정렬 |
| 생성 | `gpt-6-luna` 구조화 출력(보기별 판단 + 인용 + 근거 충족 여부) |
| 구성 | A(벡터) / B(BM25+벡터) / C(B+재정렬) / C+R(C+리라이트) |

## 2. 어떻게 검증했나

**시험지**: 2026년 변호사시험 선택형 민사법 **70문항**(DOC-04). PDF에서 한글 텍스트 추출이
안 돼 별도 텍스트 추출본을 쓴다. 2단 배치로 `① … ②`가 한 줄에 오는 23문항이 있어, 줄 머리가
아니라 ①~⑤ 표시 위치로 자르도록 파서를 만들었다.

**문항 유형이 둘이고, 이 구분이 이 보고서의 핵심 축이다.**

| 유형 | 문항 | 지문 길이(중앙값) | 보기 평균 길이 | 판단할 명제가 있는 곳 |
|---|---:|---:|---:|---|
| 일반형 | 30 | 44자 | 120자 | **보기 ①~⑤ 안** |
| 조합형 (ㄱㄴㄷㄹ) | 40 | 594자 | 6자 | **지문 안** (보기는 "ㄱ, ㄴ" 조합 기호) |

**채점 기준 2종** (CR-014로 도입):

- **① 정답 충족(번호)** — 고른 번호가 정답이면 1
- **② 근거 충족 정답** — 번호도 맞고 `evidence_sufficient=true`여야 1

**평가 무결성(C-09)**: 풀이 단계는 정답표(DOC-05)를 **읽지 않는다.** 채점 스크립트에서만 연다.
정답표는 색인·생성 프롬프트·리라이터 입력 어디에도 들어가지 않는다(INV-04).
다만 이 실험은 **평가셋의 원천을 미리 전부 풀어본 것**이므로, 평가셋 30문항을 고를 때는
이번 정오답이 아니라 미리 정한 규칙(번호·유형)으로 골라야 한다(사용자 결정 2026-11-24).

## 3. 개선 이력

### 3.1 말뭉치 범위 — CR-009 · CR-010

**문제**: 시험은 "민사법"(민법·민사소송법·상법)인데 색인은 민법 한 권뿐이었다. 민사소송법·상법
문항은 근거가 색인에 **존재하지 않아** 구조적으로 풀 수 없었다.

**조치**: 검색 문서를 **민사법 13개 법령**으로 넓혔다. 가져오기가 `statutes/*.txt` 전부를 읽고
법령 이름이 `doc_id`·인용 위치·`law_name`까지 흐르도록 바꿨다. 모듈 상수 `LAW_NAME`을 없애고
읽기 어댑터가 `StatuteFile(law_name, path, text)`를 만들어 넘긴다.

**확인**: 13개 법령 조문 4,265개가 이슈 0·버린 줄 0으로 파싱됐고, 민법 1,116조·삭제 77개라는
ADR-015의 수용 확인 수치가 그대로 유지됐다.

**곁들여 잡은 것**: `.gitignore`의 `*.json`·`*.txt`가 `eval/*.json`·`results/**/*.jsonl`·
법령 텍스트까지 무시하고 있었다. 평가셋을 만든 뒤 발견했으면 손실이 컸다.

### 3.2 데이터 정리

판시사항·판결요지가 **둘 다 빈 판례 6,706건(15.8%)**을 격리했다. 남겨 두면 가져오기가
`EMPTY_CONTENT`로 기록해 색인이 "불완전"이 되고 `eval freeze --stage final`이 막힌다.
정리 후 가져오기에서 **건너뜀 0건**이 나와, ADR-015가 심어 둔 확인 장치를 통과했다.

### 3.3 1차 측정 — 무엇이 고장나 있었나

| 결과 종류 | 문항 |
|---|---:|
| `ANSWERED` | 45 |
| `INSUFFICIENT_EVIDENCE`(기권) | 16 |
| `MODEL_ERROR` | **9** |

번호 기준 정답 58/70(82.9%). 두 가지 문제가 드러났다.

**(가) 토큰 한도** — `LengthFinishReasonError: completion_tokens=2000, reasoning_tokens=2000,
text_tokens=None`. `gpt-6-luna`는 추론 토큰을 completion 한도에서 쓰는데, 한도 2000이면
어려운 문항에서 **추론에만 다 쓰고 JSON을 한 글자도 못 내놓는다**. 9문항(12.9%)이 이렇게 날아갔다.
→ **CR-012**: `max_tokens` 제거. → **CR-017**: 시간 제한 60→90초(실측 68~76초 소요 문항 존재).

**(나) 조합형 프롬프트** — 모델이 보기 ①~⑤가 아니라 지문 속 **ㄱ~ㄹ 4개를 판정**해 스키마
검증에 걸렸다. 조합형이 70문항 중 40문항(57%)이다.
→ **CR-013**: 프롬프트에 "판단 대상은 보기 1~5, 반드시 5개 출력" 명시.

### 3.4 기권 폐지와 지표 2종 — CR-014 · 015 · 016

**관찰**: 모델이 "근거 부족"이라며 기권한 16문항 중 **14개(87.5%)가 번호는 정답**이었다.
기권하면 맞힐 수 있던 답을 버린다.

**조치**: 기권을 없앴다. 번호는 **항상** 내고, 근거 충족 여부를 `Answer.evidence_sufficient`로
따로 기록한다. `Outcome`에서 `INSUFFICIENT_EVIDENCE`를 제거했다.

```
이전: outcome = ANSWERED | INSUFFICIENT_EVIDENCE | (오류 3종)   answer_no: int | None
이후: outcome = ANSWERED | (오류 3종)                            answer_no: int (항상)
                                                                 evidence_sufficient: bool
```

이것이 **지표 ①/②를 나눠 재는 토대**다. `Grade.confident_correct`를 더해 채점표가 두 점수를
따로 담는다. 설계 문서(C-06·C-08은 `고정` 등급)까지 고쳤고, **외부 평가 기준 해석 위험**은
아래 §6.3에 적었다.

### 3.5 실패 분석 — 무엇이 남았나

2차 측정에서 틀린 10문항을 전부 뜯어봤다. **예외 없이 조합형**이었다.

- **명제 1~2개만 어긋난다.** 3개 이상 틀린 경우가 0건. 4문항은 단 하나에서 갈렸다.
  명제 수준 실력은 높은데 4개를 곱하는 구조가 점수를 깎는다.
- **실패는 두 종류**: 검색 실패 7문항(모델이 "근거가 없다"며 추정) / 법리 오판 3문항(근거를
  들고도 해석을 틀림. 문 63은 상법 제99조를 인용하고도 반대로 읽었다).
- **결정적 증거**: 모델이 "없다"던 조문이 **색인에 있었다.**
  문 8의 '혼동' = `law:민법:507-0`, 문 30의 '과실수취권' = `law:민법:587-0`·`201-0`.
  틀린 10문항의 조문 비율 **3.8%**(맞힌 60문항 9.5%), 7문항은 조문 0개.
  전체 70문항 중 **35문항(50%)이 조문을 하나도 못 받았다.**
  → **커버리지가 아니라 순위 문제.** 말뭉치가 판례 89%라 조문이 묻힌다.
- **조합형 후보가 적다**: 중앙값 11(최소 4) 대 일반형 17.5(최소 12). `n_vec=20`인데도.
  원인은 보기가 "ㄱ, ㄴ"(6자)뿐이라 **보기별 질의 5개의 원문이 사실상 같아지는 것**이다.

### 3.6 세 가지 개선 — CR-018 · 019 · 020

| CR | 무엇을 | 어떻게 |
|---|---|---|
| **018** | 조문 몫 보장 | 보기별 상위 `k_opt`(4) 안에 조문 최소 `k_law`(1)개. 모자라면 ① 목록 아래쪽 조문을 끌어올리고 ② 조문 전용 검색으로 채운다. 밀어내는 대상은 가장 낮은 **판례** |
| **019** | 2차 검색 | 1차가 근거 부족이면, 모델이 `insufficient`로 지목한 보기의 **명제만** 다시 찾아 한 번 더 답한다. **근거 충족일 때만 채택** |
| **020** | 명제 단위 질의 분해 | 조합형은 보기가 아니라 지문의 ㄱ·ㄴ·ㄷ·ㄹ **명제마다 질의 하나** |

모두 A·B·C·C+R에 같은 방식으로 적용해 구성 비교 공정성(INV-08)을 지켰다. `k_law`는
`comparable_key`에 넣었다.

- **CR-012·013·017 (토큰·프롬프트·시간)**: 오류 **9건 → 0건**. 가장 확실한 성과다.
- **CR-014~016 (기권 폐지·지표 2종)**: 기권 16문항이 답으로 바뀌었고, "풀이 능력"과

- **CR-018 (조문 몫)**: 조문 0개 문항 **35 → 0**. 의도대로 작동했다.

- **CR-020 (명제 분해)**: 조합형 ① 75.0%→77.5%, ② 40.0%→47.5%.

## 5. 퇴보 — "근거 충족" 신호의 신뢰도

| | 2차 | 3차 |
|---|---|---|
| 근거 충족 문항의 정답률 | 40/40 = **100.0%** | 45/49 = **91.8%** |
| 근거 부족 문항의 정답률 | 20/30 = 66.7% | 16/21 = 76.2% |
| **확신하며 틀린 문항** | **0건** | **4건** (10, 19, 20, 30) |

2차 측정의 가장 값진 성질은 "시스템이 근거 충족이라 하면 100% 맞다"였다. 이번에 깨졌다.

**원인 추정**: 조문 유입이 3배(8.9%→25.3%)로 늘면서 **인용할 것이 생겼다.** 모델은 조문을
인용하며 `sufficient=true`로 표시하지만 그 조문이 명제에 맞지 않으면 틀린다. 근거 충족 표시가
40→49로 9개 늘어난 것과 맞물린다. 확신 오답 4건 중 2차 검색이 채택된 것은 문 19 하나뿐이므로
CR-019 탓은 아니다.

**해석**: 지표 ②는 올랐지만 `evidence_sufficient`를 **신뢰도 신호로 쓰기는 전보다 어려워졌다.**
양을 늘리면 질이 희석되는 교환이다. 실무적으로 "근거 충족이면 92% 맞다"도 쓸 만한 신호지만,
100%였던 것과는 성격이 다르다.

## 6. 확인된 한계와 주의사항

### 6.1 결과가 실행마다 흔들린다 — 파라미터로 막을 길이 없다

실제 호출로 확인했다:

| 파라미터 | 결과 |
|---|---|
| `temperature=0` | **거부** — `Only the default (1) value is supported` |
| `top_p` | **거부** — `not supported with this model` |
| `logprobs` | **거부** |
| `seed` | 받지만 **효과 없음** — 같은 질문 8회에 3가지 답 |
| `system_fingerprint` | `None` (백엔드 변경 감지 불가) |

같은 문항을 5회씩 끝까지 돌린 결과, **리라이트 질의와 검색 컨텍스트는 매번 달랐다.**
그런데도 근거가 충분한 문항(문 2)은 답이 5회 모두 같았고, 빈약한 문항(문 9)만 갈렸다.

→ **각 측정은 1회 실행이다. ①의 +1~2문항은 노이즈 범위로 봐야 한다.**
반면 ②의 +5, 조문 0개 35→0, 확신 오답 0→4건은 구조적 변화로 보인다.

### 6.2 정답률의 상당 부분이 모델의 사전 지식일 수 있다

RAG가 **맞힌** 16문항을 골라 **문서를 하나도 주지 않고** 같은 프롬프트로 풀렸더니,
번호를 고른 11문항 중 **8문항(73%)을 그대로 맞혔다.**

선택 편향이 있어(RAG가 맞힌 것만 골랐다) 공정한 비교는 아니지만, **검색 없이도 상당수를
맞힌다**는 사실은 분명하다. **구성 A/B/C 비교에 무검색 기준선을 넣어야** 검색의 실제 기여를
분리할 수 있다.

### 6.3 외부 평가 기준 해석 위험 (가장 중요)

C-06·C-08은 등급이 `고정`이고 출처가 **외부 평가 기준 DOC-01**이다. CR-014로 기권을 없애면서
우리 문서의 문구는 고쳤지만, **채점자는 DOC-01 원문을 본다.**

DOC-01의 "근거 부족 안내" 요구를 "번호를 내되 근거가 부족하다고 표시한다"로 해석해 주는지는
**보장할 수 없다.** `report.md`에 이 해석과 근거(기권한 16문항 중 14개가 번호는 정답이었다는
실측)를 반드시 적어야 한다.

### 6.4 조문 몫은 존재를 보장할 뿐 적합성을 보장하지 않는다

문 8은 '혼동'(민법 제507조)이 필요한데 가등기담보법 제10조가 들어왔다. 보충 검색도 같은
질의를 쓰기 때문이다. 조문 전용 검색 자체는 정상이다 — "혼동으로 인한 채권 소멸"로 직접
검색하면 민법 제507조가 2위로 나온다. **질의 품질이 다음 병목이다.**

### 6.5 구성 비교가 아니다

세 측정의 `comparable_key`가 서로 다르다(`k_law` 추가). 이 문서의 비교는 **개선 전후**이지
구성 A/B/C 비교가 아니다. 본 평가는 같은 설정으로 네 구성을 돌려야 한다.

### 6.6 설계에 없어 구현 단계에서 정한 것

- `k_law = 1` (조문 몫의 크기)
- "2차 검색은 근거 충족일 때만 채택" (채택 기준)
- 2차에 더하는 후보를 `k_opt`개로 제한
- 모델이 `answer=null`을 낼 때의 대체 번호 규칙(`correct` 중 최소 → `insufficient` 중 최소 → 1)
- 조합형에서 `option_no`가 보기 번호가 아니라 질의 슬롯 번호가 되는 절충

모두 해당 ADR 개정 문구와 BE 브리핑에 근거와 함께 적었다. ARCH가 다르게 정하면 따른다.

## 7. 아직 틀리는 9문항

```
8(5/2,부족)  9(3/1,부족)  10(2/4,충족) 19(4/1,충족) 20(1/3,충족)
30(2/3,충족) 36(2/5,부족) 52(5/3,부족) 63(5/2,부족)
```

전부 조합형. **8·30은 세 차례 측정에서 계속 틀렸다** — 변동성이 아니라 구조적 실패다.
문 63은 상법 제99조를 인용하고도 반대로 해석한 **법리 오판**으로, 검색을 아무리 고쳐도 남는다.

## 8. 다음 단계 제안

1. **질의 품질** — 조문 몫이 엉뚱한 조문을 가져오는 문제(§6.4). 명제에서 법률 쟁점어를 뽑아
   조문 검색에 따로 쓰는 방법을 생각해 볼 수 있다.
2. **무검색 기준선** — 구성 A/B/C 점수에서 빼야 검색의 실제 기여가 보인다(§6.2).
3. **근거 충족 신호의 질 회복** — `k_law`를 1→0으로 되돌렸을 때와 비교해, 지표 ②와 신호
   신뢰도 중 어느 쪽을 택할지 사람이 정한다(§5).
4. **근거 부족 문항만 다수결** — 결정성을 파라미터로 못 얻으므로(§6.1) 3회 다수결이 유일한
   실무적 수단이다. 근거 충족 문항은 안 흔들리니 비용은 1.3배 수준. 다만 R-1("한 문항 = 한
   기록")과 충돌하므로 PM·ARCH 확인이 필요하다.
5. **NFR-01의 "근거 충족 정답" 목표치** — 이번 **64.3%**가 두 번째 기준선이다(이전 57.1%).
   사람이 목표를 정할 수 있다.
6. **본 평가 준비** — 평가셋 30문항 작성(§2의 무결성 주의), "근거 없음" 문항 출처 결정(CR-011),
   `eval freeze --stage final`.
